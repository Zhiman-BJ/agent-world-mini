# Agent-World Mini 代码介绍

## 1. 项目定位

Agent-World Mini 是一个小型、可审查的 Agent 环境数据生成项目。它从一个主题或 MCP/工具目录项出发，爬取真实公开数据，将数据整理成可重置的本地环境，再生成可执行工具和多步任务。项目的核心不是单纯“让 LLM 编工具和题目”，而是保证每个任务都有可追溯数据、真实参数和成功执行的参考调用链。

主要入口是 [`agent_world_mini/pipeline.py`](agent_world_mini/pipeline.py)，完整流程如下：

```text
主题 / MCP 目录项
  -> 搜索并爬取真实公开数据
  -> 构建 ResearchBundle 本地数据快照
  -> 按数据结构合成并执行验证工具
  -> 构建经过真实值检查的工具依赖图
  -> 图游走生成候选调用链
  -> 绑定真实参数、执行、去冗余和去重
  -> 语义审查并生成自然语言任务
  -> 可选 5-run 独立求解验证
```

仓库的 [`training/`](training/) 还提供后续 SFT、GRPO 和多类工具调用评测脚本，但环境数据生成主链集中在 [`agent_world_mini/`](agent_world_mini/) 中。

## 2. 爬取和整理数据

### 2.1 主题来源

主题是研究起点，不是最终数据库定义。项目支持：

- 内置公开数据主题，如 World Bank、CityBikes、Open Library、OpenAlex 和 GitHub；
- 用 `--theme` 输入自然语言主题，或用 `--source-url` 指定 MCP/工具说明页；
- 用 [`agent_world_mini/catalog.py`](agent_world_mini/catalog.py) 从 Smithery API 爬取已验证服务及工具 Schema，去除无效项和近重复项后生成本地目录。当前随仓库提供的 `prepared_environments.json` 包含 140 个预处理环境候选，批量运行时不会重新访问 Smithery。

MCP 页面中的工具只用于提示业务能力；后续数据和工具仍需根据可访问的公开数据重新构建。

### 2.2 实际爬取流程

核心实现是 [`agent_world_mini/research.py`](agent_world_mini/research.py) 中的 `WebResearchAgent`：

1. 对内置主题使用专用适配器，直接请求已知公开 API；其他主题进入通用 Web Research 流程。
2. Research Agent 通过搜索和网页抓取找到少量、具体、可读的 HTTP(S) 数据 URL，优先 JSON、CSV、公开 API 和小型文本数据。
3. `_fetch()` 先使用 Python `urllib`，失败时回退到 `curl`；JSON 直接保留，HTML 则过滤 `script/style/svg/nav/footer` 等非正文内容。多个数据源最多以 6 个线程并发抓取。
4. 如果初始结果是 API 文档，模型会将其展开为填好必需参数的只读 GET URL，再抓取真实记录，而不是把文档当作环境数据。
5. 抓取内容被转换为统一 `Record(entity_type, entity_id, attributes, source_url)`。关系通过 `*_id` 字段表示，其值必须指向另一条已有记录的 `entity_id`。
6. 扩展轮次会根据当前数据图补齐缺失的实体、关系和可达深度；如果新数据只是增加同类叶子记录而没有改善结构，就不继续无限抓取。

爬取结果统一保存为 `ResearchBundle`，主要包含 `sources`、`records`、`resources`、`state_contract`、`complexification` 和 `theme_metadata`。其数据结构定义在 [`agent_world_mini/models.py`](agent_world_mini/models.py)，落盘产物是 `runs/<slug>/research_bundle.json`。每条记录都保留 `source_url`，通用研究阶段禁止用模型知识补造业务数据。

数据研究也可替换为 Codex/Luna 外部 Research Agent 或 DeepSeek Harness，但它们只能交付同一份 `research_bundle.json`；后续工具、图和任务仍由 Python pipeline 生成。

## 3. 工具合成与验证

工具合成由 [`agent_world_mini/tools.py`](agent_world_mini/tools.py) 的 `ToolDesigner` 与 [`agent_world_mini/compiler.py`](agent_world_mini/compiler.py) 的 `EnvironmentCompiler` 共同完成。

### 3.1 从数据结构生成候选工具

`ToolDesigner` 按 `entity_type` 分组真实记录，根据已存在的字段和关系生成：

- 文本搜索和按 ID 详查：`search_*`、`get_*`；
- 数值排名和两实体比较：`rank_*`、`compare_*`；
- 按类别过滤和分组计数：`list_*_by_*`、`count_*_by_*`；
- 基于 `*_id` 或中间 link 表的一对多、多对多关系遍历工具。

`EnvironmentCompiler` 补充三类环境能力：把研究文件复制到任务工作区并读取的资源工具；对本地可变状态的 CRUD 工具；以及只在通用 CRUD/文件操作无法表达时使用的受限 Python 工具。可变数据是每次 rollout 重置的本地状态，不被当成新的真实世界事实。

每个候选工具都用 `ToolSpec` 描述名称、输入/输出、读写集合、前置工具、参数绑定、测试用例和实现后端。

### 3.2 筛选与执行验证

1. 先对结构等价的候选工具去重。
2. 可用 LLM 根据 MCP 能力线索、真实实体/关系和本地资源，选择一组连通且有业务意义的工具；模型只能从已生成的候选名称中选择，不能凭空增加工具。
3. `ToolValidator` 在 `LocalToolRuntime` 中实际执行每个工具的测试用例，检查非空结果、返回 ID、文件写入、状态变更等预期；失败工具以及前置工具已被删除的工具不会进入环境。

最终 Schema 写入 `tool_specs.json`，候选数、模型筛选依据和逐工具执行结果写入 `tool_validation.json`。

## 4. 任务合成与验证

任务不是直接根据工具列表编写，而是先找到真正能执行的数据依赖链。

### 4.1 构图与采样

[`agent_world_mini/graph.py`](agent_world_mini/graph.py) 使用三类边构建 `ToolGraph`：明确的前置/参数绑定边、对同一状态的写后读边、实体 ID 可从上游输出流入下游输入的数据边。当提供本地运行时时，构图还会用真实 ID 集合检查这条边是否确实可连通。

采样器沿连通拓扑扩展候选链，自动补入必需前置步骤，并优先关系遍历、比较、状态变更和文件处理。步数上限用于防止无限扩展，不会为了达到固定长度而硬凑调用。

### 4.2 从调用链生成任务

[`agent_world_mini/tasks.py`](agent_world_mini/tasks.py) 的 `TaskSynthesizer` 按以下流程处理每条候选链：

1. 从真实记录、上一步观测或工具测试配置中绑定参数，最多回溯 160 次，直到整条链每步都能返回有效结果。
2. 删除与其他步骤没有参数或状态依赖的孤立分量，保留最大连通的“因果核心”。
3. 拒绝重复调用、对自身进行比较的调用以及全局重复的执行序列，然后在重置的本地环境中重放因果核心。
4. 模型每批审查 4 条已执行候选，只对合理的业务目标生成自然语言请求。请求不能泄露工具名、API、Schema 或内部 ID，也不能增加执行轨迹中没有的事实。
5. 审查结果必须用 `answer_slots` 完整覆盖所保留步骤，且不能丢失任何上游观测依赖。Python 再次重放审查后的调用，生成隐藏参考链、参考答案、初始/最终状态和可校验的状态变化。

任务生成默认先采样 64 个候选，后续每批 32 个，单环境默认上限为 128；若连续两批新任务产出率低于 10% 则提前停止。未配置 LLM 时仍可爬取内置数据、生成工具并执行候选链，但不会把机械模板当作最终语义任务。

可选的 [`FiveRunVerifier`](agent_world_mini/verification.py) 会让求解模型在不可见参考链的情况下独立调用工具，最多尝试 5 次；至少 2 次给出有工具观测支撑的正确答案才保留任务。

## 5. 关键产物

每个环境默认写入 `runs/<slug>/`：

| 文件 | 内容 |
| --- | --- |
| `research_bundle.json` | 来源可追溯的记录、资源、本地状态合约和研究过程 |
| `tool_specs.json` | 通过筛选和执行验证的最终工具 Schema |
| `tool_validation.json` | 工具选择依据、测试用例及成功/失败记录 |
| `tool_graph.json` | 工具节点、真实数据流边和严格路径 |
| `walk_synthesis.json` | 原始游走、参数绑定、执行、去重和语义审查统计 |
| `tasks.json` | 最终用户请求、可见工具、隐藏参考链、参考答案和验证信息 |
| `environment_manifest.json` | 环境状态、Agent 可见边界和 rollout 重置策略 |
| `summary.json` | 记录数、工具数、图边、候选链、最终任务和 5-run 的汇总统计 |

## 6. 最小运行示例

```powershell
python -m pip install -e .

# 使用内置公开 API 主题
python -m agent_world_mini --theme-id openalex-publication-research --slug openalex-demo

# 使用自然语言主题，需要支持网页搜索/抓取的模型服务
python -m agent_world_mini --theme "研究公开的城市共享单车运营数据" --slug city-bikes

# 在普通生成后再进行高成本的 5-run 验证
python -m agent_world_mini --theme-id openalex-publication-research --slug openalex-verified --verify-five-runs
```

项目仅使用 Python 3.10+ 标准库即可运行主代码；通用 Web Research、工具语义筛选和最终任务表述需要在 `.env` 中配置可用的模型服务。更完整的命令和结果检查方法见 [`docs/USAGE_ZH.md`](docs/USAGE_ZH.md)。
