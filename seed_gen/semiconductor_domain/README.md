# Semiconductor workflow catalog

这个目录保存面向 Agent 环境生成的半导体领域分类、现实业务场景和场景型 Seed。它与
`pypi_outputs/` 中从单个 Python 包出发的旧实验产物并存，但不再以包名定义环境边界。

## 建模原则

```text
L1 生命周期阶段
  -> L2 稳定专业工作域
     -> business scenario 现实工作闭环
        -> Python 工具组合与可取得数据
           -> environment Seed
```

- 分类骨架来自路线图、标准组织和公共研发机构；它是本项目为环境生成整理的综合分类，不声称是某个
  机构发布的原始层级。
- 业务场景必须有现实工作流、标准、公开项目、论文方法或数据集支撑，不能从 Python API 名称直接推演。
- Python 包只作为实现手段。同一场景可以组合多个包，同一个包也可以服务多个场景。
- Seed 对应一组共享对象、文件、上下文和验收方式的场景，不机械对应一个 L2 或一个包。
- 公开数据不足、无法离线运行或缺少可靠验收方式的场景可以进入目录，但不会被优先选为 Seed。

## 文件

- `authoritative_sources_v1.json`：分类和业务边界使用的权威来源登记表。
- `taxonomy_v1.json`：两级领域分类。L1 是生命周期阶段，L2 是稳定专业工作域。
- `scenarios_v1.json`：约 100 个现实业务场景及其来源、数据和 Python 工具候选。
- `seed_selection_v1.json`：场景可构建性评分和 30 多个 Seed 的选择结果。
- `scenario_seeds_v1.json`：符合现有环境种子六字段结构的正式场景型 Seed 集合。
- `RESEARCH_REPORT_ZH.md`：分类综合方法、调研结论、数量分布、限制和使用方式。

## 证据要求

每个 L1/L2 至少引用一项权威来源。进入场景目录的条目至少包含：

1. 能够说明该工作域、工作目标、流程或验收方式的现实依据；
2. 明确的业务角色、输入、主要操作、输出和验收方式；
3. Python 可执行路径及数据可得性判断，或者如实标记当前不适合生成环境。

被选为正式 Seed 的场景还必须有可取得的数据、公开项目、官方完整工作流或可控仿真输入作为实现依据，
并具备可重放的验收方法。低数据可得性的场景用于保持领域地图完整，不会因为分类成立就自动成为 Seed。

场景证据优先级为：标准和权威路线图、官方端到端流程、真实项目与论文数据、公开测试/教学案例、
仅描述 API 的文档。API 文档不能单独证明业务场景成立。

## Seed 选择

Seed 候选按以下维度分别评分，而不是按工具包数量排序：

- `business_evidence`：现实工作证据是否直接、完整；
- `data_availability`：能否获得可关联、可操作的数据和领域文件；
- `python_executability`：核心操作是否能由 Python 包或 Python API 完成；
- `verification_strength`：结果能否用规则、求解器、统计量或前后差异验证；
- `workflow_depth`：是否能够形成多步、带状态和异常分支的任务。

优先选择证据、数据和验证均可靠的场景，同时保持对完整半导体生命周期的覆盖。对于 Fab MES、商业
EDA、设备维护等公开数据天然不足的领域，目录会保留真实场景，但不会用普通文档或无关数据伪装成可用 Seed。
