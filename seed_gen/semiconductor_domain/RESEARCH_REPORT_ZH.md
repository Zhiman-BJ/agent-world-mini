# 半导体业务分类、场景与 Seed 调研报告 v1

调研日期：2026-09-13 至 2026-09-14

## 1. 结论

本轮调研形成了一套面向 Agent 环境生成、覆盖半导体主要技术生命周期的两级分类：10 个 L1、50 个
L2。在该分类下整理了 100 个有现实工作依据的业务场景，并从中选择 39 个生成正式 Seed。

这套 Seed 不以单个 Python 包为锚点。分类回答“半导体领域有哪些稳定工作域”，场景回答“现实中的角色
围绕哪些对象完成什么闭环”，Python 工具只回答“这个闭环能否在当前环境中实现”。因此，一个场景可以
组合多个 Python 包、命令行求解器或 Python API，同一个包也可以出现在多个场景中。

100 个场景不等于 100 个当前都适合生成环境。公开材料可以证明晶圆制造、封装装联、质量追溯等工作真实
存在，但现实记录通常受商业保密、客户数据和设备权限限制。本轮把这些场景保留在领域地图中，同时只选择
数据、执行路径和验收方式均足够清楚的 39 个 Seed，避免用普通文档或虚构记录填补数据缺口。

## 2. 调研边界

本分类覆盖从材料发现、器件与工艺、电路设计、数字实现、版图签核，到晶圆厂运营、量测过程控制、封装、
测试良率和可靠性分析的技术工作。采购、销售、人力、通用项目管理等企业职能没有单列；它们并非半导体
技术环境独有，除非具体场景能够与 lot、wafer、die、device、design、package 等专业对象形成直接关系。

分类不是软件清单，也不是岗位清单。仿真、数据库、机器学习、优化和可视化属于横向方法，应归入实际使用
它们的工作域。具体岗位也可能横跨多个 L2，因此岗位只记录在场景中，不作为固定分类层级。

## 3. 来源与方法

### 3.1 来源结构

分类依据登记了 17 条权威来源，主要来自：

- IEEE IRDS：器件、系统、光刻、工厂集成、量测、封装和良率增强的技术边界；
- NIST CHIPS：美国 CHIPS 研发项目、量测、先进封装和可靠性方法；
- SEMI：制造设备、材料、工厂自动化和测试相关标准委员会；
- Accellera：设计、建模、验证和接口标准工作组；
- JEDEC：器件测试、资格、可靠性和封装相关委员会；
- IEEE Electronics Packaging Society：封装与异质集成路线图。

场景和实现依据另登记 80 条来源，包括 29 条官方工作流、25 条官方文档、19 个真实公开项目、2 个公开
数据集、2 项权威方法、1 份权威路线图、1 个公开基准和 1 组官方示例。两类登记表合计 97 条记录、96 个
唯一 URL。

2026-09-14 对全部 96 个 URL 做了可访问性复查：94 个直接返回 HTTP 200；SEMI 和 JEDEC 的两个官方
委员会入口返回 HTTP 403，页面受站点访问控制保护，但来源身份和入口有效。HTTP 状态只用于发现失效链接，
不替代对内容、发布者和适用范围的判断。

### 3.2 分类形成方式

没有直接照搬某一家机构的目录。本项目按以下顺序综合来源：

1. 使用 IRDS 和 NIST 确定从材料、器件到制造、封装、测试和可靠性的生命周期骨架。
2. 使用 SEMI、Accellera 和 JEDEC 补足设备自动化、设计验证、测试与资格等稳定专业边界。
3. 使用官方端到端工作流、真实开源项目、公开数据集和权威方法，把分类落到可观察的输入、状态和产物。
4. 将只描述单个函数或单个文件格式的内容降为实现证据，不让 Python API 名称反向决定业务分类。
5. 对跨域场景指定一个主要 L2；关联域保留在输入、关系和工作流中，避免重复计数。

L1 表示主要工程阶段，L2 表示具有相对稳定目标、对象、输入输出和验收方式的专业工作域。具体任务停留在
场景层，不继续机械拆成 L3，因为同一个 L2 下可能存在多种材料、产品和组织形态。

### 3.3 场景成立条件

每个场景都记录业务角色、目标、输入、至少四个主要步骤、输出、验收规则、证据、Python 实现候选和数据
可得性。API 文档只能证明一种实现能力，不能单独证明现实工作场景；场景必须同时与权威工作域、官方流程、
真实项目、公开数据或行业方法形成可解释的对应关系。

`data_availability` 的含义如下：

- `high`：存在可直接下载的真实项目、公开数据、领域文件或官方完整示例；
- `medium`：可用公开输入或受控仿真忠实重建核心状态，但现实生产记录有限；
- `low`：工作真实存在，但公开的关联业务记录不足，不适合当前直接生成环境。

## 6. 各领域调研结论

### 01 材料研究与计算发现

这个领域最适合构造文件、记录和计算状态并存的复杂环境。Materials Project、NOMAD、Matbench 等提供
材料记录，pymatgen、atomate2、jobflow、custodian、doped、phonopy 等覆盖结构处理、计算依赖、错误恢复、
缺陷和性质分析。适合的任务不是调用一次性质函数，而是维护结构版本、计算协议、任务依赖和结果血缘。

### 02 工艺技术与器件工程

真实工艺配方和 split 结果通常不公开，因此单项工艺和流程集成被保留为低可得性场景。DEVSIM、Gmsh、
Sesame、Solcore 及公开示例能够较好支撑器件结构、网格、方程、偏压扫描和光电响应；紧凑模型场景则可由
公开 I-V/C-V 曲线和约束拟合构建。Seed 重点放在可验证的器件与模型流程，而不是虚构晶圆厂配方。

### 03 电路与系统设计

开放 SPICE、Touchstone、光子 PCell 和 IP core 项目提供了丰富的网表、网络、端口、参数和仿真结果。
Python 适合编排批量仿真、PVT/蒙特卡洛、S 参数校准与级联、光子模型组合和 IP 依赖构建。复杂度来自同一
设计上下文中的多轮修改和跨产物一致性，不来自堆叠不相关工具。

### 04 数字实现与验证

cocotb、pyuvm、SymbiYosys、OpenROAD、LibreLane 和 SiliconCompiler 形成从 RTL、事务验证、形式证明到
RTL-to-GDS 的开放路径。失败日志、随机种子、VCD、反例、阶段 checkpoint 和 QoR 指标天然支持可重放、
有状态的复杂任务。该领域公开工程数据和机械验收能力都较强。

### 05 版图、掩模与签核

IHP Open PDK、SKY130、KLayout、gdstk 和开放 MPW 项目同时提供真实 GDS、工艺层、规则 deck、网表和
precheck。它们可以形成 DRC 定位与修复、LVS 对照、PDK 版本审计和流片交付检查。必须保证 PDK、规则和
版图来自兼容版本，不能把不同工艺的数据拼成一个虚假项目。

### 06 晶圆厂运营与设备

IRDS Factory Integration 和 SEMI 标准证明 lot 谱系、派工、设备状态、配方与维护是稳定业务域，但
MES、设备 trace 和真实工单很少公开。当前可行方向是使用明确 route、设备资格和事件约束做离散事件仿真，
或用 secsgem 构建协议级 host/equipment 双端。仿真必须保持流量守恒和协议状态，不应冒充真实生产记录。

### 07 量测、检测与过程控制

显微谱像和 4D-STEM 有成熟开放数据模型；SECOM 和 WM-811K 为过程异常和晶圆图形提供真实公开数据。
相反，CD、overlay、缺陷复判以及设备关联记录通常属于企业内部数据。可构建 Seed 集中在谱像分析、制造
多变量异常和 wafer map，且要求校准、坐标、批次或数据折分关系可追溯。

### 08 封装与异质集成

IRDS Packaging、NIST Advanced Packaging 和 IEEE Heterogeneous Integration Roadmap 支持完整领域
边界，但公开的 chiplet 项目 BOM、键合 DOE、bump/RDL 生产数据有限。当前选择电磁与 S 参数完整性分析，
因为 openEMS 和 scikit-rf 能提供可执行、可验收的端口网络流程；其余场景留在目录等待更好的数据源。

### 09 测试、产品与良率工程

STDF、虚拟仪器、OpenHTF 和 wafer map 数据适合构建测试记录生命周期。任务可以覆盖仪器安全状态、
lot/wafer/site/part/test/bin 关系、测试限值和 phase 优化。跨工艺、量测、缺陷和测试的真实良率根因链更
有业务价值，但公开关联数据不足，当前不应强行生成。

### 10 可靠性、质量与失效分析

NIST 可靠性方法能够支撑删失寿命数据、Weibull 和加速寿命模型，并有明确统计验收。资格试验、物理失效
分析和 CAPA 是真实核心业务，但公开样本谱系、显微证据和质量事件链不足，所以本轮仅选择寿命建模 Seed。

## 7. Seed 选择与工具关系

39 个 Seed 从 56 个初步候选中选择，另外 17 个候选延后，44 个场景因数据、执行或验收条件不足而暂不
生成。选择不是按工具数量，也不是为了让每个 L2 都机械产生一个 Seed，而是分别检查：

- 业务证据是否直接；
- 数据或领域文件是否可取得且能形成同一工作上下文；
- 核心步骤能否由 Python 包、Python API 或 Python 可调用工具完成；
- 结果能否由规则、求解器、统计量、日志或前后差异重算；
- 工作流是否具有多步状态、关系、异常或迭代，而非单函数演示。

Seed 的 `init_ref_tools` 有意保留为空数组，因为这批来源不是某个软件服务发布的 API，不应伪造“来源
自带工具”。可行 Python 组合保存在 `others.python_tool_candidates`，供 Step 1 继续核实和扩展。每个
Seed 的 `init_ref_tasks` 保存完整场景目标、输入、输出、验收和 solution path；工具可以替换，但业务对象、
关系和验收语义不能随意改变。

已选择的 Seed 覆盖以下代表性闭环：

- 材料：跨库记录治理、对称性、计算 Flow、错误恢复、带电缺陷、声子、能带和输运；
- 器件：二极管/MOS TCAD、网格收敛、紧凑模型、多结太阳能电池；
- 电路：模拟调参、PVT/蒙特卡洛、S 参数校准与级联、光子版图模型一致性、IP 依赖；
- 数字：RTL 静态审计、回归定位、UVM 风格验证、AXI、形式证明、RTL-to-GDS 恢复；
- 版图：开放 PDK DRC、LVS、PDK 版本锁定、MPW 预检查；
- 制造和量测：WIP 派工仿真、SECS/GEM、谱像、SECOM 过程异常、wafer map；
- 封装、测试和可靠性：封装互连电磁完整性、仪器扫描、STDF、测试 phase、加速寿命建模。

每个具体 Seed 的五维选择结果和理由见 `seed_selection_v1.json`，生成后的完整内容见
`scenario_seeds_v1.json`。

## 8. 已知限制与下一轮优先级

1. 晶圆厂 MES、设备 FDC、配方、维护和厂务数据的关联样本仍是最大缺口。
2. CD/overlay、缺陷复判、键合 DOE、封装 RDL 和质量 CAPA 缺少可公开重放的完整业务链。
3. 部分工作流可由 Python 编排，但底层仍依赖 ngspice、Yosys、OpenROAD、KLayout、openEMS 等外部程序；
   生成环境时必须验证运行依赖，不能仅因存在 Python wrapper 就认定可执行。
4. 官方示例和受控仿真可以验证协议、状态机和算法，但必须在 provenance 中标明其性质，不能称为真实生产
   记录。
5. 领域分类追求稳定边界，不追求把每个材料体系、产品类型或工具都变成分类节点。新增内容应优先扩展场景，
   只有出现新的稳定业务对象和验收边界时才调整 L2。

下一轮最有价值的补充不是继续增加工具包，而是寻找能够连接多个业务对象的公开项目数据，例如：lot-route-
equipment-event、wafer-metrology-defect-test、package-layout-port-measurement、sample-stress-failure-analysis。

## 9. 产物与复现

核心文件：

- `authoritative_sources_v1.json`：17 条分类权威依据；
- `workflow_sources_v1.json`：80 条工作流、项目、数据和实现依据；
- `taxonomy_v1.json`：10 个 L1、50 个 L2；
- `scenarios_v1.json`：100 个业务场景；
- `seed_selection_v1.json`：39 个选择及五维理由；
- `scenario_seeds_v1.json`：39 条正式 Seed；
- `seed_build_report_v1.json`：机器可读数量和分布报告。

从目录重新生成 Seed：

```bash
cd /home/sunshuo/AgenticDataGeneration/agent-world-mini
python -m seed_gen.scripts.build_semiconductor_scenario_seeds
```

执行专用验收：

```bash
pytest -q tests/test_semiconductor_scenario_seeds.py
```

将其中一个 Seed 交给现有 DataGen：

```bash
PYTHONPATH=. python -m env_gen.data_gen \
  --seed-path seed_gen/semiconductor_domain/scenario_seeds_v1.json \
  --global-id semiconductor_scenario_catalog_sc_01_03_03_8 \
  --schema-path schemas/environment.schema.json \
  --output-dir /tmp/semiconductor-sc-01-03-03 \
  --overwrite
```

这里的 `global_id` 只用于示例；批量运行时应按 `seed_build_report_v1.json` 中的
`generated_global_ids` 枚举，并为每个 Seed 使用独立输出目录。
