# 两个 Python 包的半导体应用预处理

## 调研结论

本次采用“工具包是能力锚点、半导体是领域过滤条件、真实应用链决定环境内容”的规则。一个 Seed 仍以一个
目标包为核心，但不把 Python 包边界误当成完整工作环境，也不排斥完成实际任务所需的协作包。

`atomate2` 和 `pymatgen-core` 在半导体研究中是上下游关系，但承担不同的核心作用，因此保留为两个 Seed：

```text
pymatgen-core
  结构/组成 -> 输入输出文件 -> 能带/DOS/结构分析

atomate2
  Maker -> Job/Flow -> 计算阶段依赖 -> TaskDocument/结果存储
```

atomate2 的现实工作流使用 `jobflow` 表达依赖、用 `custodian` 处理 VASP 错误、用 `emmet-core` 表示结果
文档，并由 FireWorks 或 jobflow-remote 提交到计算资源；缺陷和输运应用还会调用
`pymatgen-analysis-defects` 与 `AMSET`。pymatgen-core 可以独立完成结构和文件处理，但在端到端计算中更常
作为 atomate2、doped、sumo、PyTASER 和 AMSET 的数据对象与解析层。这些协作关系应进入环境描述和后续
数据链，不能因为 Seed 锚定一个包而被排除。

本次不按 API 数量拆分，也不为每个物性建立一个 Seed。每个包保留一个半导体应用 Seed，只覆盖能在明确的
半导体项目、论文或成熟下游包中核实的应用链。只有当后续数据无法共享材料标识、结构版本和计算上下文时，
才考虑按应用另建 Seed。

## 半导体中的真实使用方式

### atomate2

公开的光伏研究项目 `mattheww98/PV_paper` 用 pymatgen 从 CIF 读取 13 种光伏半导体，通过 atomate2 的
`UniformBandStructureMaker`、`HSEOpticsMaker` 和 powerup 生成 GGA/HSE 能带与光学工作流，再用 jobflow
转换成 FireWorks 工作流提交。仓库保存 79 份覆盖 GGA/HSE static、bands、gap 和 optics 阶段的
`vasprun.xml`，并提供配套 OUTCAR、WAVEDER 与结构文件。

数据库级带电缺陷项目 `jmmshn/run_defects` 使用 `MPGGADoubleRelaxMaker`、`MPGGAStaticMaker`、
`FormationEnergyMaker` 和不同缺陷/电荷态的 relax/static/HSE Maker，保存 LOCPOT、CHGCAR 与 WAVECAR，
同时依赖 pymatgen、pymatgen-analysis-defects、jobflow、FireWorks 和 emmet-core。这两类项目表明，半导体
中的 atomate2 不是孤立文件解析器，而是连接候选材料、批量计算、调度和结果存储的工作流层。

因此 atomate2 Seed 的核心不是“有很多 VASP 结果”，而是要能说明并尽量取得：

- 同一材料的结构、Maker 配置、Job/Flow 依赖和阶段状态；
- 每个阶段的输入目录、输出目录、TaskDocument 和性质对象；
- 真实计算数据与作业标识之间的可追溯关系。

筛选出的半导体应用族包括：光伏候选的 GGA/HSE 结构弛豫、静态、能带、DOS、介电和光学流程；母体、缺陷
超胞及不同电荷态的形成能计算链；以及以能带、介电、弹性和形变势为输入的 AMSET 载流子输运。普通声子、
独立铁电、通用电子-声子和文件压缩/删除/重命名等没有在本次真实半导体项目中形成核心任务的 API 不纳入 Seed。

公开的 Materials Project、NOMAD、AFLOW、JARVIS 数据可以提供真实结构和计算结果，但不一定公开 atomate2/jobflow 的序列化依赖图。这个缺口必须如实记录，不能用普通 VASP 文件假装补齐。

### pymatgen-core

真实半导体项目通常不把 pymatgen 当成单独的端到端应用，而是把它作为共同数据层：光伏项目用 `Structure`
读取 CIF 并向 atomate2 传递结构；doped 用结构匹配、VASP 解析、LOCPOT/CHGCAR 和相图数据完成带电缺陷、
化学势、形成能和费米能级分析；sumo 用 pymatgen 读取 VASP 能带、DOS 和光学结果；PyTASER 直接使用
`Vasprun`、`Waveder`、`FermiDos` 和 Materials Project 数据模拟半导体瞬态吸收；AMSET 用 pymatgen 的结构、
能带和对称性对象计算迁移率、散射率和输运性质。半导体使用中的共同主线是：

```text
真实晶体结构/掺杂候选
  -> Structure 与格式转换
  -> VASP 输入和真实计算输出
  -> 带隙、能带、DOS、对称性和结构匹配
```

相稳定性、化学势、掺杂/替位和缺陷筛选不是任意扩展，而是带电缺陷工作流中确定竞争相、形成能和载流子
浓度所需的直接步骤；它们必须有组成、结构、体相/缺陷能量和电荷等真实输入。

筛选出的半导体应用族包括：晶体结构与格式转换、对称性和结构匹配、缺陷超胞操作、相稳定性与化学势、
VASP 输入输出、计算收敛与结构变化、能带/DOS/光学、电荷与局域势，以及输运所需的弹性数据。普通声子、
分子、表面吸附、晶界、分子动力学和仅在包内展示、但未进入上述真实半导体应用链的 API 不纳入 Seed。

## 是否需要拆分

当前不拆成多个 Seed，原因是：

1. 两个包各自都有一条连贯的半导体主线；拆成“结构、能带、声子、缺陷……”会把同一材料和同一计算链切碎。
2. `atomate2` 与 `pymatgen-core` 本来就是上下游包，分成两个包 Seed 可以保留职责边界，同时允许后续使用相同的材料和 VASP 来源进行对照。
3. 光伏电子/光学、缺陷和输运仍共享 Structure、VASP 阶段文件、Job/Flow 与结果文档。只有后续实际数据无法
   用材料、结构和作业标识关联时，才值得再拆。

## Seed 生成规则

- 保留原始包名、版本、来源 URL 和原有六个顶层字段；`others` 仍只包含原 Seed 已有的
  `python_source_extraction`，不增加应用画像或调研字段。
- 重新编写环境描述，使 Step 1 能从中识别半导体中的实际对象、任务链和外部求解器边界。
- `init_ref_tools` 采用逐模块的核心符号白名单，只保留能够直接参与上述半导体任务链的类和函数；不再因为
  某个模块整体相关，就把其中所有公共辅助函数一并纳入。同步收窄 `requested_modules` 和 `source_files`，
  使三者表达同一个能力边界。
- 保留 `init_ref_tasks` 为空，因为原 PyPI Seed 没有来源任务，不能把本次调研推导出的任务伪装成包作者提供的参考任务。
- 两个派生 Seed 各自保存为只含一条记录的 JSON 数组，同时生成一份同结构的两条记录集合用于批量运行。
