# Agent-World Mini 任务契约 v1.0

结构示例见 [task.schema.json](task.schema.json)；机器校验规则见
[validation/task.schema.json](validation/task.schema.json)。

## 1. 完整任务是什么

完整任务依据完整环境和工具的数据信息生成，描述交给 Agent 的任务、可用工具、初始状态，以及仅供验证和评测使用的参考信息。生成过程中不引入完整环境和真实工具执行以外的额外信息来源，任务文本、参考答案和资源约束由 LLM 生成并经过验证

完整任务 JSON 只允许以下九个顶层字段：

```text
schema_version / task_id / environment_id / task_text / difficulty /
initial_state / available_tools / resource_constraints / reference
```

根对象禁止额外字段。生成过程、失败记录、运行配置和评测结果会存储于 bundle 等文件，不属于完整任务 JSON。

## 2. 任务包目录

一个任务包对应一次任务生成运行，一次运行针对一个环境生成多个任务。使用的环境、LLM 和时间等运行信息记录在 `run.json` 中。

```text
<taskgen_run>/
├── tasks.json                 # 所有通过验证的任务，每个任务遵循任务 Schema
├── run.json                   # 本次任务生成过程的配置和记录信息
├── rejected.json              # 生成失败的任务及原因，后续可用于重试
├── tasks/                     # 该环境中各任务的数据文件工作区
│   └── <task_id>/
│       ├── initial/           # 环境初态，用于任务执行初始化
│       └── final/             # 参考链执行后的状态，用于任务执行效果评测
└── intermediate/              # 每一步的完整 Bundle，用于调试及可视化
    └── step_<n>_bundle.json
```

`tasks.json` 是完整任务数组。同一次运行中，每个任务的 `initial/` 内容相同，但目录相互独立；`final/` 是从各自 `initial/` 执行参考调用链后的状态。每个阶段的 Bundle 包含截至该阶段已有的全部中间产物字段。`run.json`、`rejected.json` 和 `intermediate/` 都不属于单个完整任务。

## 3. 顶层字段

| 字段 | 类型 | 精确定义 |
| --- | --- | --- |
| `schema_version` | string | 任务契约版本；v1.0 固定为 `"1.0"` |
| `task_id` | string | 同一个 `tasks.json` 内唯一且稳定的 ID，使用小写 `snake_case` |
| `environment_id` | string | 所属完整环境的 ID |
| `task_text` | string | 交给 Agent 的自然语言任务 |
| `difficulty` | object | 从参考轨迹计算的难度；v1.0 只包含 `tool_calls` |
| `initial_state` | string | 相对本次运行目录的任务初始工作区路径 |
| `available_tools` | array | 本任务允许 Agent 调用的公开工具契约 |
| `resource_constraints` | object | 规定任务执行后哪些资源必须、可以或不得发生净变化 |
| `reference` | object | Agent 不可见的参考调用、参考答案和最终状态 |

## 4. `task_text`

`task_text` 必须同时满足：

1. 描述用户希望得到的业务结果或状态变化，不罗列工具调用和操作步骤。
2. 提供完成任务所需且无法由 Agent 自行发现的业务信息，例如目标名称、指定内容、时间范围或格式要求。
3. 不出现工具名、`resource_id`、内部 ID、数据库主键、工作区路径、临时句柄或其他用户不可理解的实现信息。
4. 表达自然、目标明确、边界清晰，像人话
5. 与参考调用链一致；按该调用链能够完成任务的全部要求。

可以通过公开环境、初始工作区或查询工具发现的信息不写入任务。参考答案和执行结果不得提前泄漏到任务文本中。

## 5. 难度、状态与工具

`difficulty` 目前只以进行了几次工具调用来体现：

```json
{"tool_calls": 6}
```


`initial_state` 和 `reference.final_state` 即参考调用链执行前后的 workspace 的路径，分别固定为 `tasks/<task_id>/initial` 和 `tasks/<task_id>/final`。它们相对本次运行目录解析，禁止绝对路径和 `..` 路径段；两个目录必须存在且不得包含符号链接。

`available_tools` 等于所属完整环境全部 `tools[]` 移除 `internal` 后的公开投影，每个元素只包含：

```text
name / description / inputSchema / outputSchema
```

工具字段的含义以 [工具契约 v1.0](工具契约-v1.0.md) 为准。

## 6. `resource_constraints`

```json
{
  "should_modify": [],
  "can_modify": [],
  "must_not_modify": []
}
```

| 字段 | 含义 |
| --- | --- |
| `should_modify` | 完成任务必须发生变化的资源 |
| `can_modify` | 合理解法可以修改，但不要求必须变化的资源 |
| `must_not_modify` | 任何合理执行都不得改变的资源 |

三个数组中的元素必须是所属环境的 `resource_id`，数组之间互不相交。`writable=false` 的资源不得出现在 `should_modify` 或 `can_modify` 中。未出现在任何数组中的资源默认不得修改。

## 7. `reference`

`reference` 只供验证和评测使用：

```json
{
  "tool_calls": [
    {"tool": "tool_name", "arguments": {}}
  ],
  "answer": "参考答案",
  "final_state": "tasks/example_task/final"
}
```

- `tool_calls` 是从 `initial_state` 真实成功执行的调用记录，数组顺序就是执行顺序。
- 每个 `tool` 必须存在于 `available_tools`，`arguments` 必须通过对应 `inputSchema`。
- `answer` 是依据全部参考调用结果整理的完整答案，由llm生成，生成时可访问除internal code外的全部信息。
- `final_state` 必须是依次执行全部参考调用后保存的工作区。

## 8. 可见边界

求解 Agent 获得 `task_text`、公开环境和由 `initial_state` 准备的工作区；公开环境中的工具与 `available_tools` 一致。工具的 `internal`、`resource_constraints` 和整个 `reference` 不得提供给求解 Agent。

Runtime 使用 `initial_state` 准备独立工作区并提供公开工具。Evaluator 使用 `resource_constraints`、`reference`、实际调用记录、实际答案和执行后的工作区判断任务是否完成。

## 9. 必须验证的跨字段规则

JSON Schema 之外，Validator 还必须检查：

1. `environment_id` 等于所属完整环境的 `environment_id`。
2. `available_tools` 等于完整环境工具的公开投影，工具名唯一。
3. `difficulty.tool_calls` 等于 `reference.tool_calls` 的数量。
4. 参考调用使用存在的工具，参数通过对应 `inputSchema`，且全部真实执行成功。
5. `initial_state` 与环境初始工作区一致，`reference.final_state` 是参考调用执行后的状态。
6. 资源约束只引用环境中存在的资源，三个数组互不相交，并符合资源的 `writable` 属性。
7. `initial_state` 到 `reference.final_state` 的实际变化符合资源约束；未列出的资源保持不变。
8. `task_text` 包含完成任务所需信息，并与参考调用链及其结果一致。

## 10. 不进入完整任务 JSON 的内容

以下内容保存在运行旁路文件中：

```text
生成配置、模型和时间信息          run.json
未通过验证的候选及失败原因        rejected.json
所有llm调用的记录               llm_calls.json
工具图、采样链、LLM 审查和阶段产物 intermediate/
Agent 实际执行与评测结果          TaskEval 结果目录
```
