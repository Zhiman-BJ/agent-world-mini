# Agent-World Mini 可执行环境包 v2.0

本文定义 DataGen v2 环境与可执行工具交给 ToolGen Runtime 和 TaskGen 时的
包级边界。它不改变 `environment.json` 的闭合结构，也不把工具实现混入
数据环境声明。

## 1. 物理结构

```text
<environment_package>/
├── environment.json
├── validation.json
├── state/
│   ├── records.sqlite
│   └── filesystem_scopes/<scope_id>/...
└── tools.json
```

- `environment.json` 符合 `环境契约-v2.0.md` 和 `environment.schema.json`；
- `validation.json.valid` 必须为 `true`；
- `state/` 与环境契约中的 Record Set 和 Filesystem Scope 一致；
- `tools.json` 保存通过工具契约和执行验证的工具。

## 2. `tools.json`

权威格式是：

```json
{
  "tools": [
    {
      "name": "list_items",
      "description": "List items that are visible in the current environment.",
      "inputSchema": {},
      "outputSchema": {},
      "internal": {
        "code": "def run(arguments, context):\n    ..."
      }
    }
  ]
}
```

`tools[]` 每项必须通过 `validation/tool.schema.json`。TaskGen Loader 过渡期也接受
直接以数组为根的工具文件，但新 ToolGen 产物应使用上述 object 形式。

## 3. 公开和内部边界

任务设计 Agent 和求解 Agent 只能看到：

```text
name / description / inputSchema / outputSchema
```

Runtime 和 Validator 可以额外读取：

```text
internal.code
```

`internal.code` 不得写入任务文本、Agent 工具列表、Prompt 公开上下文或
求解轨迹。

## 4. v2 ToolContext

Runtime 调用：

```python
run(arguments, context)
```

`context` 固定提供：

```python
context.state_root: pathlib.Path
context.records_path: pathlib.Path
context.filesystem_scopes_root: pathlib.Path
context.scope_root(scope_id: str) -> pathlib.Path
context.workspace_root: pathlib.Path
```

`workspace_root` 是旧工具契约的兼容别名，v2 中与 `state_root` 相同。
新工具应使用 `records_path` 访问 SQLite，使用 `scope_root(scope_id)` 访问
指定 Scope。

## 5. 状态和事务边界

1. 每次 rollout 从基线 `state/` 的独立副本开始；
2. `read_only` Record Set 和 Scope 不得变化；
3. `copy_on_write` 只修改当前 rollout 副本；
4. 未声明表、SQLite schema、Scope 外文件和 `state/` 其他路径不得变化；
5. 工具返回 `success=false` 时，本次调用的所有数据库和文件变化必须回滚；
6. 输入先通过 `inputSchema`，返回先通过 `outputSchema`，然后才向 Agent 暴露。

## 6. 不属于本契约的信息

ToolGen 的能力盘点、生成 Prompt、测试用例、修复记录和通过率是旁路产物，
不进入 `tools.json`。TaskGen 的任务、参考程序和最终状态也不进入环境包。
