# Agent-World Mini 环境契约 v1.0

结构示例见 [environment.schema.json](environment.schema.json)；机器校验规则见
[validation/environment.schema.json](validation/environment.schema.json)。

## 1. 协议位置和边界

该协议是环境生成阶段的最终输出，也是工具生成阶段的输入。它描述一个不带工具的文件工作区：

```text
环境种子
  -> 环境生成
  -> 本协议：环境信息 + resources[] + rules[]
  -> 工具生成
  -> 完整可执行环境
```

该协议只说明环境是什么、包含哪些资源，以及资源之间必须满足什么规则，不包含工具、任务或 Runtime 实现。

完整顶层结构固定为：

```text
schema_version / environment_id / name / description / resources / rules
```

## 2. 完整示例

```json
{
  "schema_version": "1.0",
  "environment_id": "semiconductor_layout_001",
  "name": "芯片版图验证工作区",
  "description": "包含原始版图、抽取后的版图实体、设计规则和分析工作区。",
  "resources": [
    {
      "resource_id": "raw_layouts",
      "name": "原始版图",
      "description": "客户提交的原始 GDSII 芯片版图文件。",
      "data_type": "raw",
      "storage_type": "file_collection",
      "path": "layouts/*.gds",
      "format": "gdsii",
      "writable": false
    },
    {
      "resource_id": "layout_entities",
      "name": "版图实体数据",
      "description": "从原始版图中抽取出的 cell、layer 和 geometry 实体记录。",
      "data_type": "entity",
      "storage_type": "file",
      "path": "entities/layout_entities.json",
      "format": "json",
      "writable": false,
      "source_resources": ["raw_layouts"],
      "entity_schema": {
        "cell": {
          "description": "版图中的 cell 实体。",
          "fields": {
            "cell_id": {
              "type": "string",
              "description": "cell 的稳定标识，供 geometry.cell_id 引用。"
            },
            "name": {
              "type": "string",
              "description": "版图文件中保存的 cell 名称。"
            }
          }
        },
        "layer": {
          "description": "版图中的工艺层实体。",
          "fields": {
            "layer_id": {
              "type": "string",
              "description": "工艺层的稳定标识，供 geometry.layer_id 引用。"
            },
            "layer_number": {
              "type": "integer",
              "description": "GDSII 文件中的 layer number。",
              "minimum": 0
            },
            "datatype": {
              "type": "integer",
              "description": "与 layer number 配套的 GDSII datatype。",
              "minimum": 0
            }
          }
        },
        "geometry": {
          "description": "版图中的几何图形实体。",
          "fields": {
            "geometry_id": {
              "type": "string",
              "description": "几何图形的稳定标识。"
            },
            "cell_id": {
              "type": "string",
              "description": "该图形所属 cell 的标识，引用 cell.cell_id。"
            },
            "layer_id": {
              "type": "string",
              "description": "该图形所在工艺层的标识，引用 layer.layer_id。"
            },
            "geometry_type": {
              "type": "string",
              "description": "图形的 GDSII 几何类别。",
              "enum": ["boundary", "path", "text", "box"]
            }
          }
        }
      }
    },
    {
      "resource_id": "layer_statistics",
      "name": "层统计结果",
      "description": "根据版图实体计算出的各层面积和图形数量。",
      "data_type": "derived",
      "storage_type": "file",
      "path": "derived/layer_statistics.json",
      "format": "json",
      "writable": false,
      "source_resources": ["layout_entities"]
    },
    {
      "resource_id": "reports",
      "name": "分析报告目录",
      "description": "工具生成的检查报告、图片和中间结果。",
      "data_type": "output",
      "storage_type": "directory",
      "path": "reports/",
      "format": "directory",
      "writable": true
    }
  ],
  "rules": [
    {
      "description": "geometry.cell_id 必须引用存在的 cell.cell_id。",
      "resources": ["layout_entities"]
    },
    {
      "description": "geometry.layer_id 必须引用存在的 layer.layer_id。",
      "resources": ["layout_entities"]
    }
  ]
}
```

## 3. 顶层字段

### 3.1 `schema_version`

```json
"schema_version": "1.0"
```

表示环境协议版本。v1.0 固定为字符串 `1.0`，不是环境内容版本、数据版本或工具版本。

### 3.2 `environment_id`

```json
"environment_id": "semiconductor_layout_001"
```

环境的稳定唯一标识，使用小写 `snake_case`。名称或描述调整但环境身份不变时，ID 不变；生成了另一份独立环境时必须使用新 ID。

### 3.3 `name`

```json
"name": "芯片版图验证工作区"
```

供 Prompt、索引和人工审核使用的简短名称。`name` 不要求全局唯一，也不能代替 `environment_id`。

### 3.4 `description`

```json
"description": "包含原始版图、抽取后的版图实体、设计规则和分析工作区。"
```

说明环境模拟的现实业务场景、数据范围和主要用途。它描述整个环境，不重复逐个资源的文件名，也不提前列举尚未生成的工具。

### 3.5 `resources`

环境中实际存在或明确预留的文件、同类文件集合和目录。数组至少包含一个资源。每个资源由唯一 `resource_id` 标识。

### 3.6 `rules`

无法仅靠单个文件格式表达的业务规则。可以是空数组，但不能省略。规则可以约束一个资源内部的字段，也可以约束多个资源之间的一致性。

## 4. 资源公共字段

每个资源都必须包含：

```text
resource_id / name / description / data_type / storage_type / path / format / writable
```

### 4.1 `resource_id`

```json
"resource_id": "layout_entities"
```

环境内部的稳定资源标识，使用小写 `snake_case`，并在 `resources[]` 中唯一。`source_resources` 和 `rules[].resources` 只能引用这里声明的 ID，不能引用路径或资源名称。

### 4.2 `name`

```json
"name": "版图实体数据"
```

面向人和生成模型的简短资源名称。它可以使用中文或英文，不作为引用键，也不要求唯一。

### 4.3 `description`

```json
"description": "从原始版图中抽取出的 cell、layer 和 geometry 实体记录。"
```

说明资源中保存什么数据、数据覆盖什么范围，以及它在现实工作流中的用途。不要只把 `path` 或 `format` 换一种说法。

### 4.4 `data_type`

`data_type` 描述数据在环境中的语义类别，不描述磁盘格式。

| 值 | 精确定义 |
| --- | --- |
| `raw` | 环境收集或接收的原始数据。即使原始文件是 JSON 或 CSV，只要没有被环境重新抽取为统一实体，仍然属于 `raw` |
| `entity` | 从一个或多个资源中抽取、清洗并规范化的实体、关系或业务记录；必须声明 `source_resources` 和 `entity_schema` |
| `derived` | 根据其他资源计算、转换或汇总得到的数据；必须声明 `source_resources`，但不声明 `entity_schema` |
| `output` | 为工具调用结果预留的文件或目录；初始时可以为空，必须允许写入 |

以下分类是错误的：

```text
原始 CSV 因为有行列结构就标成 entity       错误，未规范化时仍是 raw
JSON 格式就标成 entity                     错误，format 不决定 data_type
工具运行后产生的报告标成 derived           错误，任务执行期产生的内容属于 output
环境初始化前已经计算好的统计表标成 output   错误，基线中已存在的计算结果属于 derived
```

### 4.5 `storage_type`

`storage_type` 描述一个资源在工作区中对应什么范围，不描述资源内容。

| 值 | `path` 含义 | 初始存在性 |
| --- | --- | --- |
| `file` | 一个确定文件的相对路径，不使用 glob | 文件必须存在 |
| `file_collection` | 选择一组同格式文件的 POSIX glob | 初始化时必须至少匹配一个文件 |
| `directory` | 一个目录的相对路径 | 非 `output` 目录必须存在；`output` 目录可由 Loader 创建 |

`file_collection` 中所有匹配文件必须使用同一个 `format`。异构目录不能伪装成一个 `file_collection`，应拆成多个资源，或作为 `directory` 资源处理。

### 4.6 `path`

```json
"path": "layouts/*.gds"
```

路径相对于环境包固定的工作区根目录。协议不重复保存绝对工作区路径。

路径规则：

```text
使用 POSIX 分隔符 /
禁止绝对路径
禁止 . 和 .. 路径段
file 使用确定路径
file_collection 可以使用 *、? 和 ** glob
directory 使用目录路径；结尾的 / 可由 Loader 统一规范化
```

`path` 是物理位置，`resource_id` 是逻辑引用。其他字段必须引用 `resource_id`，避免文件移动后导致关系失效。

### 4.7 `format`

```json
"format": "gdsii"
```

资源的物理编码或注册格式，用于选择解析器。使用小写稳定标识，不写带点扩展名，也不写工具包名称。

示例：

```text
json / jsonl / csv / parquet / sqlite
text / markdown
gdsii / oasis / lef / def / liberty
touchstone / spice
png / svg / pdf
directory
```

`format` 与 `data_type` 是两个独立维度。例如原始 API 响应和规范化实体记录都可以是 `json`，但它们分别属于 `raw` 和 `entity`。

当 `storage_type=directory` 时，`format` 固定为 `directory`。目录内部包含多种格式时，通过目录内容或其他资源条目分别描述，不能给目录虚构一个文件格式。

### 4.8 `writable`

```json
"writable": false
```

表示工具是否被允许改变该资源范围内的文件内容或目录成员。

| 值 | 含义 |
| --- | --- |
| `false` | 只读。工具调用后内容、文件集合和路径都必须保持不变 |
| `true` | 可以由工具修改，但只允许通过经过验证的工具实现，不代表 Agent 获得直接文件系统权限 |

`output` 资源必须使用 `writable=true`。`raw` 通常只读，但协议允许现实业务中的原始工作文件可写；`entity` 和 `derived` 是否可写由环境业务决定。

## 5. 来源字段 `source_resources`

```json
"source_resources": ["raw_layouts"]
```

表示当前资源由同一环境中的哪些资源产生。数组元素必须是现有 `resource_id`，顺序不表达处理顺序。

规则：

```text
entity     必须包含至少一个 source_resources
derived    必须包含至少一个 source_resources
raw        不包含 source_resources
output     不包含 source_resources
```

资源不能引用自身，来源关系不能形成环。多个来源表示当前资源的内容同时依赖这些资源，不表示只需任选一个。

`source_resources` 只表达环境内部的数据血缘，不保存网页 URL、文件哈希或生成脚本。

## 6. `entity_schema`

`entity_schema` 只允许出现在 `data_type=entity` 的资源中，用于描述该资源内规范化的实体和关系记录。

```json
{
  "cell": {
    "description": "版图中的 cell 实体。",
    "fields": {
      "cell_id": {
        "type": "string",
        "description": "cell 的稳定标识，供其他实体引用。"
      },
      "name": {
        "type": "string",
        "description": "版图文件中保存的 cell 名称。"
      }
    }
  }
}
```

### 6.1 实体名称

`cell` 是实体类型名称，使用小写 `snake_case`。同一 `entity_schema` 内不能重复。关系记录也作为实体类型声明，例如 `project_member` 或 `cell_layer_usage`。

### 6.2 实体 `description`

说明一条记录在现实业务中的含义，而不是简单重复实体名称。

### 6.3 `fields` 中的字段 Schema

`fields` 保留实体字段名到字段定义的映射。每个字段至少包含 `type` 和 `description`，写法与工具 `inputSchema.properties` 中的参数定义相同：

```json
"recorded_at": {
  "type": "string",
  "description": "该版图快照完成写入的 UTC 时间。",
  "format": "date-time"
}
```

`type` 只允许以下标量 JSON 类型：

```text
string / integer / number / boolean
```

`description` 必须说明字段保存什么业务值、单位或标识作用；不能只写“字符串字段”“状态字段”或重复字段名。根据字段类型可以补充：

| 关键字 | 适用字段 | 用途 |
| --- | --- | --- |
| `format` | string | `date`、`date-time`、`time`、`duration`、`email`、`hostname`、`ipv4`、`ipv6`、`uri`、`uuid` |
| `enum` / `const` | 任意标量 | 声明环境真实允许的有限值或固定值 |
| `pattern` | string | 声明稳定编码、路径或标识格式 |
| `minLength` / `maxLength` | string | 约束文本长度 |
| `minimum` / `maximum` | integer、number | 声明包含边界的数值范围 |
| `exclusiveMinimum` / `exclusiveMaximum` | integer、number | 声明不包含边界的数值范围 |
| `multipleOf` | integer、number | 声明计量步长或精度 |

这些约束必须来自真实数据格式或业务规则，不能根据当前少量样本随意收窄。例如只观察到 `open` 和 `closed`，但来源允许 `pending` 时，`enum` 必须包含三者。

所有列出的字段在每条对应实体记录中都必须出现且不能为 `null`。v1.0 不在实体字段内嵌套 object 或 array。原始文件中的复杂对象保留在 `raw`，需要稳定查询和关联的嵌套内容应规范化为独立实体或关系实体。

字段名使用小写 `snake_case`。`*_id` 只是命名约定，不会自动建立关系；外键或跨实体约束必须写入 `rules[]`。

### 6.4 实体资源的文件布局

为避免同一个 `entity_schema` 对应多种无法判断的文件结构，v1.0 固定解释如下：

| `format` | 文件内容与 `entity_schema` 的对应关系 |
| --- | --- |
| `json` | 根对象的 key 是实体名称，value 是该实体记录数组 |
| `jsonl` | 一个资源只能声明一种实体，每一行是一条记录 |
| `csv` | 一个资源只能声明一种实体，首行为字段名，其余行为记录 |
| `parquet` | 一个资源只能声明一种实体，列名对应 `fields` |
| `sqlite` | 实体名称对应表名，字段名称对应列名 |

其他格式不得标记为 `entity`，除非在新协议版本中明确其记录布局。

## 7. `rules[]`

规则对象固定包含：

```json
{
  "description": "geometry.cell_id 必须引用存在的 cell.cell_id。",
  "resources": ["layout_entities"]
}
```

| 字段 | 含义 |
| --- | --- |
| `description` | 一条完整、可判断真假的业务约束，不使用模糊建议语言 |
| `resources` | 该规则涉及的一个或多个 `resource_id`，至少包含一个且不能重复 |

规则可用于表达：

```text
实体字段引用关系
跨资源主键或名称一致性
单位、范围和时间约束
只允许追加而不允许覆盖
配置必须覆盖原始文件中的全部类型
派生结果必须与来源资源保持一致
```

规则不保存工具调用顺序、测试结果或 Runtime 实现方式。

## 8. 字段组合约束

| `data_type` | 必需附加字段 | 禁止字段 | 常见 `writable` |
| --- | --- | --- | --- |
| `raw` | 无 | `source_resources`、`entity_schema` | 通常 `false` |
| `entity` | `source_resources`、`entity_schema` | 无 | 由业务决定 |
| `derived` | `source_resources` | `entity_schema` | 通常 `false` |
| `output` | `writable=true` | `source_resources`、`entity_schema` | 固定 `true` |

资源数组还必须满足：

```text
resource_id 在环境内唯一
file 路径指向一个实际文件
file_collection 至少匹配一个实际文件
directory 格式固定为 directory
source_resources 的引用全部存在且无环
rules[].resources 的引用全部存在
entity 文件内容符合 entity_schema 的固定布局
只读资源在工具调用前后保持不变
```

这些属于协议约束，即使 JSON Schema 无法单独表达跨数组唯一性和引用完整性，Loader/Validator 也必须检查。

## 9. 不进入环境协议的内容

以下内容不属于不带工具环境：

| 信息 | 所属阶段 |
| --- | --- |
| 工具名称、描述和输入输出 Schema | 工具生成阶段 |
| Python 工具代码和依赖环境 | 工具生成阶段 |
| 工具测试、通过率和执行日志 | 工具验证旁路产物 |
| Runtime handler、事务实现和 reset 算法 | Runtime 全局协议 |
| DAG 边、reads/writes 和参数传递关系 | TaskGen 内部材料 |
| 任务文本、参考调用和答案 | 任务生成阶段 |
| 文件哈希、扫描日志和缓存 | Loader/审计旁路材料 |

环境协议不直接暴露给求解 Agent。求解 Agent 只看到当前任务允许使用的公开工具及工具调用返回结果。
