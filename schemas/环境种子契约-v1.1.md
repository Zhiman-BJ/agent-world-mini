# Agent-World Mini 环境种子契约 v1.1

结构示例见 [env_seeds.schema.json](env_seeds.schema.json)，内容是真实场景种子 `02.02.01` 的完整产物；机器校验规则见
[validation/env_seeds.schema.json](validation/env_seeds.schema.json)（包级基底 Schema，场景形态由生成器在其上显式适配，
见 [build_physics_scenario_seeds.py](../seed_gen/scripts/build_physics_scenario_seeds.py) 的 `scenario_validator`）。
MCP 与 Python 包的阅读样例分别见 [mcp种子示例1_v1.1.json](../seed_gen/mcp种子示例1_v1.1.json) 和
[python包种子示例.json](../seed_gen/python包种子示例.json)；场景种子当前产物见
[scenario_seeds/](../seed_gen/pypi_outputs/scenario_seeds/) 及其 [README](../seed_gen/pypi_outputs/scenario_seeds/README.md)。

两个阅读样例含 `"..": "..."`、中文注释 key 等省略说明，不是可整体提交给机器 Schema 的正式数据；正式字段及约束以本文、结构示例和 `validation/env_seeds.schema.json` 为准。

## 1. 定位与边界

环境种子是环境生成的上游输入，用于描述来源、环境方向及来源自带的工具和任务线索。它不是可执行环境，也不是最终工具或任务协议。

```text
MCP / 单个 Python 包采集 --> 包级种子（schema_version "1.1"）
包级种子 --按场景组合、多包合并--> 场景种子（schema_version "scenario-1.0"，当前产物）
场景种子 -> 环境生成 -> environment.schema.json
         -> 工具生成 -> tool.schema.json
         -> 任务生成
```

`init_ref_tools` 和 `init_ref_tasks` 仅供后续生成参考。来源能力必须经过重新设计、实现和验证后，才能成为 Agent 可调用的正式工具。

## 2. 种子形态与版本标记

v1.1 覆盖两种种子形态，由 `schema_version` 区分，同一产物内不得混写：

| 形态 | `schema_version` | `basic_info` / `others` | 当前产物 |
| --- | --- | --- | --- |
| 包级种子 | `"1.1"` | 单个对象 | Smithery MCP 集合、单个 Python 包种子 |
| 场景种子 | `"scenario-1.0"` | 按包顺序的数组 | `scenario_seeds/*.json`、`semiconductor_scenario_02_0916.json` |

`schema_version` 标记数据形态代次，不与本文版本号同步递增。`scenario-1.0` 是 v1.1 契约定义的当前形态；使用独立标记是为了与 `basic_info`/`others` 为对象的旧包级 `"1.1"` 数据明确区分。

## 4. v1.1 变更

### 4.1 v1.0 -> v1.1（包级形态）

| 位置 | v1.0 | v1.1 |
| --- | --- | --- |
| `schema_version` | `"1.0"` | `"1.1"` |
| `basic_info.url` | 单个 URI 字符串 | 一个或多个 URI 组成的数组 |
| `basic_info.version` | 无 | 必填字符串 |
| MCP 工具输入 | `inputSchema` | `input` 参数映射 |
| MCP 工具输出 | 可选 `outputSchema` | `function` 工具必填 `output` |
| 工具身份 | 无 | 必填 `type` 和 `module` |
| 工具数量 | 隐含于数组长度 | `environment.nums` 按工具类型明确记录 |

旧 `inputSchema`/`outputSchema` 根节点的 `type: object` 不进入新字段；其 `properties` 内容分别成为 `input`/`output`。

### 4.2 包级形态 -> 场景形态（当前产物的格式微调）

| 位置 | 包级形态 | 场景形态 |
| --- | --- | --- |
| `schema_version` | `"1.1"` | `"scenario-1.0"` |
| `global_id` | `{source}_{normalized_name}_{index}` | `{领域家族}_scenario_{场景编号}`，编号中的点号改为下划线 |
| `basic_info` | 单对象 | 包信息数组，每项在包级 `basic_info` 基础上并入原包级 `environment.description` |
| `environment` 新增字段 | — | `scenario` / `pypi_package` / `package_relation` / `possible_task`（均必填） |
| `domain` | `snake_case` 分类 ID，允许为 `null` | “编号 + 空格 + 名称”的层级编码，三级均非空 |
| `others` | 单对象 | 按包顺序的数组，逐包原样保留包级 `others` |
| `init_ref_tools` | 单包选集 | 多包选集按 `module/name/type` 合并，类方法按名去重，冲突报错 |
| `init_ref_tasks` | 来源任务 | 当前为空数组；任务方向由 `possible_task` 表达 |

## 5. 顶层字段

### 5.1 `schema_version`

按第 2 节取 `"1.1"`（包级）或 `"scenario-1.0"`（场景级）。它是种子结构版本，不是来源软件版本。

### 5.2 `global_id`

全局 ID 使用小写 `snake_case`。

包级种子生成规则：

```text
{source}_{normalized_name}_{index}
```

`normalized_name` 将 `name` 中连续的非 ASCII 字母数字字符替换为单个下划线，去掉首尾下划线并转为小写。JSON Schema 不能重算该值，生成器或 Validator 必须验证它与 `source/name/index` 一致且在集合中唯一。

场景种子生成规则：

```text
{领域家族}_scenario_{场景编号}
```

`场景编号` 即 `domain.level3` 的编号，点号替换为下划线，如 `02.02.01` -> `semiconductor_scenario_02_02_01`。同一集合内场景编号不得重复。

### 5.3 `environment`

场景种子固定包含 `basic_info`、`scenario`、`description`、`pypi_package`、`package_relation`、`possible_task`、`domain` 和 `nums`；包级种子只包含 `basic_info`、`description`、`domain` 和 `nums`。可选的 `description_zh` 只用于中文展示，不能替代来源原文 `description`。

### 5.4 `init_ref_tools` 与 `init_ref_tasks`

二者必须是数组。空数组表示没有对应内容；不能使用 `null` 或内容全为 `null` 的占位对象。场景种子当前没有来源任务，`init_ref_tasks` 固定为空数组，`possible_task` 只提供任务设计方向。

### 5.5 `others`

场景种子中 `others` 是与 `basic_info` 同序的数组，每项保存对应包的 `source_metadata` 等次要来源信息。工具数量统一由 `environment.nums` 表达，不再放入 `others`。

## 6. `environment.basic_info`

场景种子的 `basic_info` 是包信息数组，每项字段：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `source` | string | 来源目录或提供方的稳定 `snake_case` 标识 |
| `url` | array[string] | 该包至少一个不重复的可追溯绝对 URI（仓库、包索引、文档等） |
| `name` | string | 来源中的稳定包名，保留大小写 |
| `version` | string | 来源发布版本、快照版本或采集日期，非空 |
| `index` | integer | 该包在来源快照中的原序号，保留包级取值 |
| `description` | string | 原包级 `environment.description` 原文，非空 |

约束：

- `pypi_package[i]` 逐字等于 `basic_info[i].name`，且与 `others` 长度一致、顺序对应。
- 每项 `description` 描述对应包的能力；场景整体描述在 `environment.description`。
- URL 不得包含令牌、密钥或本机临时路径。

包级种子的 `basic_info` 是单对象，字段同上表去掉 `description`，示例见 MCP 阅读样例。

## 7. 场景字段与分类

| 字段 | 规则 |
| --- | --- |
| `scenario` | 场景短名，逐字对应场景维护表 |
| `description` | 场景具体描述，说明要建立的模型、求解内容与边界 |
| `pypi_package` | 实际贡献工具的包名数组，非空去重，逐字使用 `basic_info` 中的包名（含大小写） |
| `package_relation` | 包间关系标注（可替代 / 互补等），逐字对应场景维护表 |
| `possible_task` | 可合成任务方向；不是最终任务 Prompt、标准答案或验证器 |

`domain` 固定三级且均非空，使用“编号 + 空格 + 名称”的层级编码：

```json
{
  "level1": "半导体 02 器件与物理仿真",
  "level2": "02.02 Carrier",
  "level3": "02.02.01 Mobility / Scattering"
}
```

编码逐级一致：`level3` 编号以 `level2` 编号为前缀，`level2` 编号属于 `level1` 领域；`global_id` 中的场景编号与 `level3` 编号一致。包级种子仍使用 `snake_case` 分类 ID 并允许为 `null`；上级为 `null` 时所有下级也必须为 `null`。

## 8. `environment.nums`

`nums` 统一记录初始参考工具的分类数量：

```json
{
  "class": 0,
  "function": 12,
  "class_func": 0,
  "all_func": 12
}
```

| 字段 | 含义 |
| --- | --- |
| `class` | `init_ref_tools` 中 `type == "class"` 的顶层工具数 |
| `function` | `init_ref_tools` 中 `type == "function"` 的顶层工具数 |
| `class_func` | 所有 class 工具的 `function` 数组长度之和 |
| `all_func` | 可调用函数总数，必须等于 `function + class_func` |

四项均为非负整数。计数口径为 `all_func = function + class_func`，包含源选集已统计的构造方法和属性，不代表每项都是可直接独立调用的函数；顶层条目数 = `class + function`，类容器不折算为单个操作。Smithery MCP 参考工具全部是顶层 function，因此 `class = 0`、`class_func = 0`，且 `function = all_func = len(init_ref_tools)`。Python 包允许同时包含 class 和 function；顶层 class 本身不计入 `all_func`。场景种子按多包合并后的工具集合重算。

## 9. `init_ref_tools`

### 9.1 公共字段

每个参考工具至少包含：

```text
name / type / module / description / input
```

| 字段 | 规则 |
| --- | --- |
| `name` | 来源工具、函数或类名，非空；可以保留点号、连字符和大小写 |
| `type` | `function` 或 `class` |
| `module` | Python 模块路径，非空；MCP 工具固定为 `null` |
| `description` | 来源能力说明；来源未提供时保留空串并单独报告（见 9.6） |
| `description_zh` | 可选中文展示译文，不替代来源原文 |
| `input` | 输入参数映射；无参函数为 `{}`；Python 类为原始基类或构造签名字符串，未记录时为空串 |

### 9.2 `function` 工具

`function` 类型还必须包含 `output`：

```json
{
  "name": "get_region_list",
  "type": "function",
  "module": "devsim",
  "description": "Gets a list of regions on a device, contact, or interface.",
  "input": {
    "device": {
      "type": "str",
      "description": "The selected device"
    },
    "contact": {
      "type": "str, optional",
      "description": "If specified, gets the name of the region belonging to this contact on the device"
    }
  },
  "output": null,
  "ori_input": "device, contact, interface",
  "ori_description": "devsim.get_region_list (device, contact, interface) ……"
}
```

`input` 是参数名到参数定义的直接映射，不再包裹 `type/properties`。`output` 保存来源返回字段映射；Python 工具来源未声明返回时为 `null`，MCP 工具来源未声明时写空对象 `{}`。两种空值都表示“来源未声明返回结构”，不表示工具没有返回值。Python 提取器可额外保存 `ori_input` 和 `ori_description` 以保留原始签名及文档。

### 9.3 `class` 工具

Python 类使用 `type: "class"`、非空 `module`，并通过 `function` 数组保存类方法：

```json
{
  "name": "Plottings",
  "type": "class",
  "module": "mobilitypy.mobility",
  "input": "_plot_mobilities",
  "description": "Plotting class for mobilitypy.",
  "function": [
    {
      "name": "__init__",
      "description": "Intializing mobilitypy Plotting class.",
      "input": {
        "self": null,
        "save_figure_dir": {
          "type": "str, optional",
          "description": "Directory where to save the figure. The default is current directory."
        }
      },
      "output": null,
      "ori_input": "self, save_figure_dir = '.'",
      "ori_description": "Intializing mobilitypy Plotting class.  Parameters ---------- save_figure_dir : str, optional Directory where to save the figure. The default is current directory."
    }
  ]
}
```

类方法固定包含 `name/description/input/output`，并可带 `ori_input/ori_description`；方法 `input` 中 `self`/`cls` 参数的值为 `null`。

### 9.4 多包合并

场景种子的工具来自多个包的选集，合并规则：

- 按 `module + name + type` 归并同一身份；函数要求逐字段相等。
- 同一类的 `function` 方法按名称去重，重复方法必须逐字段相等。
- 任何身份或方法冲突都是生成错误，不得静默覆盖，也不得在种子层删除来源声明。

### 9.5 与正式工具契约的区别

种子参考工具保存来源能力线索，不直接套用 [tool.schema.json](tool.schema.json)：

| 项目 | 种子参考工具 | 正式公开工具 |
| --- | --- | --- |
| 名称 | 保留来源命名及可能的重复声明 | 必须符合正式工具命名和唯一性规则 |
| 输入输出 | 来源参数/返回定义的直接映射，可不完整 | 完整 JSON Schema 与运行协议 |
| 实现 | 不要求可执行 | 必须提供并验证实现 |
| 保证 | 不保证状态、回滚或确定性 | 必须满足正式工具契约 |

### 9.6 来源空说明

来源未提供说明时 `description` 保留空字符串 `""`，校验时将此类 `minLength` 例外单独报告并计数；不得补造文案，也不得为此放宽 Schema。其余结构错误必须为零。

## 10. `init_ref_tasks`

来源提供任务时，每项包含：

```json
{
  "description": "Find and compare relevant records.",
  "input": {"query": "example"},
  "output": {"summary": "expected result"},
  "solution_path": [
    "Search the records",
    {"tool_name": "compare_records", "arguments": {"record_ids": ["a", "b"]}}
  ]
}
```

这些字段保存来源证据，不是最终任务 Prompt、标准答案或验证器。来源未提供任务时使用空数组，不推测调用参数或伪造答案；场景种子当前 `init_ref_tasks` 均为空数组，任务方向由 `possible_task` 表达。

## 11. `others` 与命名规则

场景种子的 `others` 按包顺序逐项保留包级 `others`，每项固定包含三个一级 key：

| key | 内容 |
| --- | --- |
| `source_metadata` | 仓库、发布标签、commit、核对日期、子模块状态等来源快照 |
| `python_source_extraction` | 静态提取策略、源文件清单及 sha256、docstring 映射规则、`runtime_verified` |
| `python_api_selection` | 包级筛选配置与计数（`selected_*`、`boundary`、`target_all_func` 等） |

`python_api_selection` 中的计数是包级来源快照，不是场景级统计；场景级数量以 `environment.nums` 为准。

`others` 是开放对象，其一级自定义 key 使用小写 `snake_case`。旧字段 `others.tool_count` 已迁移为 `environment.nums`，`others.data_directions` 和 `others.organization_status` 已删除；v1.1 正式产物不得再写入这三个字段。嵌套的来源原始载荷可保留原 key。`iconUrl`、缓存和临时错误不属于核心字段。`others` 不能覆盖 `global_id`、`basic_info.url/name/version` 的含义。

## 12. JSON Schema 之外的校验

机器 Schema 负责字段存在性、基本类型、固定层级和对象封闭性。以下关系必须由生成器或 Validator 补充检查：

```text
global_id 按所属形态的规则可重算，且在整个集合中唯一
场景编号与 domain.level3 编号一致
basic_info、pypi_package、others 长度一致，pypi_package[i] 等于 basic_info[i].name
others[i] 是对应包级种子 others 的原样拷贝
scenario/description/package_relation/possible_task 与场景维护表逐字一致
domain 三级编码逐级一致
environment.nums 可由 init_ref_tools 重算
```
