# Agent-World Mini 环境种子契约 v1.0

结构示例见 [env_seeds.schema.json](env_seeds.schema.json)；机器校验规则见
[validation/env_seeds.schema.json](validation/env_seeds.schema.json)。

## 1. 协议位置和边界

环境种子是环境生成阶段的上游输入，用于回答“从哪里生成什么环境，以及来源提供了哪些能力线索”。它不是可执行环境，也不是最终环境、工具或任务协议。

```text
环境种子集合
  -> 环境生成
  -> 环境契约：environment.schema.json
  -> 工具生成与验证
  -> 工具契约：tool.schema.json
  -> 任务生成
```

三个边界必须分开：

| 数据 | 作用 | 是否可直接交给求解 Agent |
| --- | --- | --- |
| 环境种子 | 保存来源、环境描述、分类及可选的参考工具和任务 | 否 |
| 环境契约 | 描述生成后的工作区资源和业务规则 | 否 |
| 公开工具契约 | 描述 Agent 实际可调用的工具输入和输出 | 是 |

种子中的 `init_ref_tools` 和 `init_ref_tasks` 只为后续生成提供参考，不要求原样复刻，也不能跳过正式生成和验证直接发布。

## 2. 文档结构

一个正式环境种子文件是 JSON 数组。数组中的每个对象是一条独立种子：

```json
[
  {
    "global_id": "smithery_theagenttimes_news_1",
    "schema_version": "1.0",
    "environment": {
      "basic_info": {
        "source": "smithery",
        "url": "https://smithery.ai/servers/theagenttimes/news",
        "name": "theagenttimes/news",
        "index": 1
      },
      "description": "Agent News is a research and verification service for the AI-agent economy.",
      "domain": {
        "level1": "general",
        "level2": null,
        "level3": null
      }
    },
    "init_ref_tools": [
      {
        "name": "tat_search",
        "description": "Search documented agent-news records.",
        "inputSchema": {
          "type": "object",
          "properties": {
            "query": {
              "type": "string"
            }
          }
        },
        "outputSchema": {
          "type": "object"
        }
      }
    ],
    "init_ref_tasks": [],
    "others": {
      "source_metadata": {
        "qualified_name": "theagenttimes/news"
      }
    }
  }
]
```

正式条目的顶层字段固定为：

```text
global_id / schema_version / environment / init_ref_tools / init_ref_tasks / others
```

这六个字段都必须出现。`init_ref_tools` 和 `init_ref_tasks` 没有内容时使用空数组，`others` 没有内容时使用空对象。这样可以区分“来源明确没有提供”和“生成器漏写字段”。

[`env示例1_v1.json`](../seed_gen/data/env示例1_v1.json) 同时包含带中文 key 的注释条目，并用 `"..": "..."` 省略了工具内容；这些写法只用于阅读，不属于正式数据。批量机器产物以 [`smithery_140_v1_0824.json`](../seed_gen/data/smithery_140_v1_0824.json) 为准。

## 3. 顶层字段

### 3.1 `schema_version`

```json
"schema_version": "1.0"
```

表示环境种子契约版本。v1.0 固定为字符串 `1.0`。它不表示来源目录版本、环境内容版本、环境契约版本或工具契约版本。

### 3.2 `global_id`

```json
"global_id": "smithery_theagenttimes_news_1"
```

环境种子的稳定全局标识，使用小写 `snake_case`。生成规则是：

```text
{source}_{normalized_name}_{index}
```

`normalized_name` 将 `name` 中连续的非 ASCII 字母数字字符替换为一个下划线，去掉首尾下划线并转为小写。例如：

```text
source = smithery
name   = theagenttimes/news
index  = 1
结果   = smithery_theagenttimes_news_1
```

同一份种子集合中 `global_id` 必须唯一。JSON Schema 可以检查格式，但不能根据另外三个字段重新计算 ID，也不能只按某个对象字段检查数组唯一性；生成器或 Validator 必须补做这两项检查。

### 3.3 `environment`

环境主体，固定包含 `basic_info`、`description` 和 `domain`。这里只描述环境生成方向，不声明最终文件、数据库、资源关系或业务规则；这些内容由环境生成后按照 [环境契约 v1.0](环境契约-v1.0.md) 写入。

### 3.4 `init_ref_tools` 和 `init_ref_tasks`

来源自带的工具和任务线索。两个字段都必须是数组：

```json
"init_ref_tools": [],
"init_ref_tasks": []
```

空数组表示来源未提供对应内容。不要创建内容全为 `null` 的占位工具或占位任务。

### 3.5 `others`

保存不属于环境、参考工具和参考任务核心结构的次要信息，例如目录快照字段、连接信息、整理状态和研究方向。它不能替代核心字段，也不能把核心字段复制一份后改名保存。

## 4. `environment.basic_info`

### 4.1 `source`

来源目录或提供方的稳定标识，使用小写 `snake_case`，例如 `smithery`。它描述种子记录来自哪里，不表示后续环境使用的业务数据都来自该网站。

### 4.2 `url`

可直接回溯到来源记录的绝对 URI。Smithery 条目的确定性规则为：

```text
https://smithery.ai/servers/{name}
```

URL 必须指向具体种子条目，不能只写目录首页，也不能使用本机临时文件路径代替来源。鉴权信息、访问令牌和密钥不得写入 URL。

### 4.3 `name`

来源中的稳定名称。Smithery 条目固定使用来源原始 `qualifiedName`，例如 `theagenttimes/news`，不使用 `displayName`，也不从 `namespace` 和 `slug` 重新拼接。

`name` 可以包含来源命名所需的 `/`、`-`、`.` 或其他字符，因此不强制 `snake_case`。只有自定义字段名和本项目生成的 ID 使用 Python 命名法。

### 4.4 `index`

该来源快照中的正整数序号，从 `1` 开始。它用于在同名或重新导入场景中形成确定性 ID，不代表质量排名或使用量排名。

## 5. 环境描述与分类

### 5.1 `description`

`description` 是非空字符串，至少应覆盖：

```text
环境模拟的现实业务或工作流
主要处理的数据或实体范围
核心能力和预期用途
影响环境生成的重要限制或边界
```

描述环境本身，不逐项复述来源工具名，不声称尚未采集的数据已经存在，也不把目录宣传文案直接当作事实保证。

### 5.2 `domain`

分类固定为最多三级：

```json
{
  "level1": "general",
  "level2": null,
  "level3": null
}
```

每一级保存稳定的 `snake_case` 分类标识，而不是展示名称。没有更细分类时用 `null`，不能使用空字符串、`none` 字符串或省略字段。

层级必须连续：

```text
level1 == null  -> level2 和 level3 都必须为 null
level2 == null  -> level3 必须为 null
level3 非 null  -> level1 和 level2 都必须非 null
```

完全未分类时三个值均为 `null`。当前 Smithery 140 条产物统一使用 `general / null / null`。三级分类值本身就是分类 ID；v1.0 不额外增加分类对象 ID、标签或置信度。需要统一分类词表时，应单独维护词表并由 Validator 检查，不能在单条种子中自由扩展第四级。

## 6. `init_ref_tools`

每个参考工具至少包含：

```text
name / description / inputSchema
```

来源提供时再保留 `outputSchema`。

| 字段 | 规则 |
| --- | --- |
| `name` | 来源工具名，非空并原样保留；可以含点号或连字符 |
| `description` | 来源提供的非空能力说明 |
| `inputSchema` | 来源声称为输入 JSON Schema 的对象；根节点必须是 `type: object`，内部参数名和关键字原样保留 |
| `outputSchema` | 可选；来源声称为输出 JSON Schema 的对象，来源未声明时保持字段缺失 |

缺少 `outputSchema` 表示“来源没有提供输出 Schema”，不表示工具没有返回值。不得为了通过格式检查补写 `null` 或凭空补造输出结构。

环境种子契约只确认这两个字段是来源提供的 JSON 对象，不确认其中每个关键字都符合某个 JSON Schema 草案。来源内容即使不完整或元校验失败也应原样保留，同时在质量审计中报告；生成最终工具时必须重新设计和校验，不能把来源错误带入正式契约。

### 6.1 与正式工具契约的区别

参考工具不能直接 `$ref` [tool.schema.json](tool.schema.json)，因为二者承担不同职责：

| 项目 | 种子参考工具 | 正式公开工具 |
| --- | --- | --- |
| 名称 | 保留来源名称，可含 `-` 或 `.` | 必须为小写 `snake_case` |
| 输入 | 允许来源 Schema 不完整 | 必须是封闭 object，完整声明 `properties/required/additionalProperties` |
| 输出 | 可以为普通来源 Schema，也可以不提供 | 必须用两个 `oneOf` 分支声明成功和业务失败 |
| 语义 | 能力线索 | Agent 可依赖的运行协议 |
| 状态保证 | 来源种子不作保证 | 必须满足正式工具契约的回滚、确定性和读写边界 |

当前 `smithery_140_v1_0824.json` 包含 2,833 个参考工具，其中 401 个来源名称不符合正式工具的 `snake_case` 规则，1,020 个没有 `outputSchema`，另有 11 个来源 `outputSchema` 对象不能通过 Draft 2020-12 元校验。这些是保留来源信息后的合法种子状态，不是可直接发布的工具状态。

环境和工具生成阶段必须重新设计、规范化并验证正式工具，最终产物再按照 [工具契约 v1.0](工具契约-v1.0.md) 校验。

## 7. `init_ref_tasks`

来源提供任务时，每个任务固定包含：

```json
{
  "description": "Find and compare the relevant records.",
  "input": {
    "query": "example"
  },
  "output": {
    "summary": "expected result shape or example"
  },
  "solution_path": [
    "Search the relevant records",
    {
      "tool_name": "compare_records",
      "arguments": {
        "record_ids": ["a", "b"]
      }
    }
  ]
}
```

| 字段 | 规则 |
| --- | --- |
| `description` | 非空的来源任务描述 |
| `input` | 来源任务输入，可保留任意合法 JSON 值 |
| `output` | 来源任务期望输出，可保留任意合法 JSON 值 |
| `solution_path` | 参考解决步骤数组；元素可以是非空字符串或结构化对象 |

这些字段保存来源证据，不是最终任务的 Prompt、标准答案或验证器。若来源只提供了模糊文字，应保留可确认的信息，不应推测工具调用参数或伪造参考答案。当前 Smithery 140 条产物没有 Agent-World 参考任务，因此统一使用空数组。

## 8. `others` 与命名规则

`others` 是开放对象。当前 Smithery 转换产物使用：

```text
source_metadata / data_directions / organization_status
```

规则如下：

1. `others` 的一级自定义 key 使用小写 `snake_case`。
2. 项目新增的嵌套 key 也应使用小写 `snake_case`。
3. 为保持来源可追溯性，嵌套保存的来源原始载荷可以保留原始 key 和字段值。
4. 爬取工具的参数名、JSON Schema 关键字和枚举值必须原样保留，不执行批量改名。
5. `iconUrl`、缓存、抓取日志和临时错误不属于核心种子字段；是否保留由具体采集策略决定。
6. `others` 中的信息不能覆盖 `global_id`、`basic_info.url`、`basic_info.name` 等核心字段的含义。

## 9. JSON Schema 之外的校验

`validation/env_seeds.schema.json` 使用 JSON Schema Draft 2020-12，负责字段存在性、基本类型、固定层级和对象封闭性。外层 `env_seeds.schema.json` 只作为契约结构示例。以下跨条目或来源语义必须由生成器或 Validator 额外检查：

```text
global_id 等于 source、规范化 name 和 index 的确定性组合
global_id 在整个集合中唯一
同一 source 快照中的 index 唯一
url 能回溯到 source/name 指定的具体来源条目
同一环境内参考工具 name 不重复
来源 inputSchema/outputSchema 的元校验问题已审计和报告，但不在种子层静默修复
正式数据中不存在中文注释 key、".."、"..." 等说明性占位
```

对当前批量产物执行机器校验的示例：

```powershell
python -c "import json; from pathlib import Path; from jsonschema import Draft202012Validator, FormatChecker; s=json.loads(Path('agent_world_mini/schemas/validation/env_seeds.schema.json').read_text(encoding='utf-8')); d=json.loads(Path('agent_world_mini/seed_gen/data/smithery_140_v1_0824.json').read_text(encoding='utf-8')); Draft202012Validator(s, format_checker=FormatChecker()).validate(d); print(len(d))"
```

预期输出为 `140`。该命令只验证种子格式，不代表环境资源、正式工具实现、Runtime 状态或任务执行已经通过验收。

## 10. v1.0 生成检查清单

```text
1. 文件是 UTF-8 编码的合法 JSON 数组，且至少包含一条种子。
2. 每条种子只包含六个固定顶层字段，schema_version == "1.0"。
3. global_id 可重算、格式正确且在集合中唯一。
4. source、url、name、index 都存在，url 可追溯，index 为正整数。
5. description 非空，domain 固定为连续的三级结构。
6. 无参考工具或任务时写空数组，不写 null，不省略字段。
7. 参考工具保留来源内容；来源没有 outputSchema 时保持字段缺失。
8. 参考任务若存在，完整写入 description/input/output/solution_path。
9. 其余信息进入 others；自定义 key 使用 Python 命名法。
10. 参考工具和任务经过生成与验证后，才进入正式环境、工具或任务产物。
```
