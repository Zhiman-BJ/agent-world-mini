> 文件名为兼容已有链接暂保留 `环境种子契约-v1.0.md`；本文及机器校验规则已升级为 v1.1。

结构示例见 [env_seeds.schema.json](env_seeds.schema.json)，机器校验规则见
[validation/env_seeds.schema.json](validation/env_seeds.schema.json)。MCP 与 Python 包的阅读样例分别见
[mcp种子示例1_v1.1.json](../seed_gen/mcp种子示例1_v1.1.json) 和

两个阅读样例含 `"..": "..."`、中文注释 key 等省略说明，不是可整体提交给机器 Schema 的正式数据；正式字段及约束以本文、结构示例和 `validation/env_seeds.schema.json` 为准。

## 1. 定位与边界

环境种子是环境生成的上游输入，用于描述来源、环境方向及来源自带的工具和任务线索。它不是可执行环境，也不是最终工具或任务协议。

```text
环境种子 -> 环境生成 -> environment.schema.json
         -> 工具生成 -> tool.schema.json
         -> 任务生成
```

`init_ref_tools` 和 `init_ref_tasks` 仅供后续生成参考。来源能力必须经过重新设计、实现和验证后，才能成为 Agent 可调用的正式工具。

## 2. v1.1 总体结构

正式文件是 JSON 数组，每个对象是一条独立种子：

```json
[
  {
    "global_id": "smithery_theagenttimes_news_1",
    "schema_version": "1.1",
    "environment": {
      "basic_info": {
        "source": "smithery",
        "url": [
          "https://smithery.ai/servers/theagenttimes/news"
        ],
        "name": "theagenttimes/news",
        "version": "2026-09-02",
        "index": 1
      },
      "description": "Agent News is a research and verification service for the AI-agent economy.",
      "domain": {
        "level1": "general",
        "level2": null,
        "level3": null
      }
    },
    "init_ref_tools": [
      {
        "name": "tat_search",
        "type": "function",
        "module": null,
        "description": "Search documented agent-news records.",
        "input": {
          "query": {
            "type": "string",
            "description": "Search query."
          }
        },
        "output": {
          "text": {
            "type": "string",
            "description": "Text response when supplied by the source."
          }
        }
      }
    ],
    "init_ref_tasks": [],
    "others": {
      "source_metadata": {
        "qualified_name": "theagenttimes/news"
      },
      "tool_count": 1
    }
  }
]
```

顶层固定包含：

```text
global_id / schema_version / environment / init_ref_tools / init_ref_tasks / others
```

六个字段均不可省略。没有参考工具或任务时写空数组；`others` 至少包含 `tool_count`。

## 3. v1.1 变更

相较 v1.0，本版统一 MCP 和 Python 包种子，变更如下：

| 位置 | v1.0 | v1.1 |
| --- | --- | --- |
| `schema_version` | `"1.0"` | `"1.1"` |
| `basic_info.url` | 单个 URI 字符串 | 一个或多个 URI 组成的数组 |
| `basic_info.version` | 无 | 必填字符串 |
| MCP 工具输入 | `inputSchema` | `input` 参数映射 |
| MCP 工具输出 | 可选 `outputSchema` | `function` 工具必填 `output` |
| 工具身份 | 无 | 必填 `type` 和 `module` |
| 工具数量 | 隐含于数组长度 | `others.tool_count` 明确记录 |

旧 `inputSchema`/`outputSchema` 根节点的 `type: object` 不进入新字段；其 `properties` 内容分别成为 `input`/`output`。来源没有输出定义时，`output` 使用空对象 `{}`，表示“来源未声明返回字段”，不表示工具没有返回值。

## 4. 顶层字段

### 4.1 `schema_version`

v1.1 固定为字符串 `"1.1"`。它是种子结构版本，不是来源软件版本。

### 4.2 `global_id`

全局 ID 使用小写 `snake_case`，生成规则为：

```text
{source}_{normalized_name}_{index}
```

`normalized_name` 将 `name` 中连续的非 ASCII 字母数字字符替换为单个下划线，去掉首尾下划线并转为小写。JSON Schema 不能重算该值，生成器或 Validator 必须验证它与 `source/name/index` 一致且在集合中唯一。

### 4.3 `environment`

固定包含 `basic_info`、`description` 和 `domain`。可选的 `description_zh` 只用于中文展示，不能替代来源原文 `description`。

### 4.4 `init_ref_tools` 与 `init_ref_tasks`

二者必须是数组。空数组表示来源没有提供对应内容；不能使用 `null` 或内容全为 `null` 的占位对象。

### 4.5 `others`

保存来源元数据、研究方向、整理状态等次要信息，并必须包含实际参考工具数量 `tool_count`。

## 5. `environment.basic_info`

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `source` | string | 来源目录或提供方的稳定 `snake_case` 标识 |
| `url` | array[string] | 至少一个不重复的可追溯绝对 URI |
| `name` | string | 来源中的稳定名称；Smithery 使用原始 `qualifiedName` |
| `version` | string | 来源发布版本、快照版本或采集日期，非空 |
| `index` | integer | 来源快照中的正整数序号 |

Smithery v1.1 数据使用：

```json
{
  "source": "smithery",
  "url": ["https://smithery.ai/servers/theagenttimes/news"],
  "name": "theagenttimes/news",
  "version": "2026-09-02",
  "index": 1
}
```

Python 包可以同时列出包索引、源码仓库和文档地址。URL 不得包含令牌、密钥或本机临时路径。

## 6. 环境描述与分类

`description` 是非空来源描述，至少应能表达业务场景、数据或实体范围、核心能力和主要限制。不能声称尚未采集的数据已经存在。

分类固定为连续的三级结构：

```json
{
  "level1": "general",
  "level2": null,
  "level3": null
}
```

每级使用稳定的 `snake_case` 分类 ID。若上级为 `null`，所有下级也必须为 `null`；没有分类时三个字段均为 `null`。

## 7. `init_ref_tools`

### 7.1 公共字段

每个参考工具至少包含：

```text
name / type / module / description / input
```

| 字段 | 规则 |
| --- | --- |
| `name` | 来源工具、函数或类名，非空；可以保留点号、连字符和大小写 |
| `type` | `function` 或 `class` |
| `module` | Python 模块路径；MCP 工具固定为 `null` |
| `description` | 来源提供的非空能力说明 |
| `description_zh` | 可选中文展示译文，不替代来源原文 |
| `input` | 输入参数映射；Python 类也可保留原始构造签名字符串或 `null` |

### 7.2 `function` 工具

`function` 类型还必须包含 `output`：

```json
{
  "name": "search",
  "type": "function",
  "module": null,
  "description": "Search source records.",
  "input": {
    "query": {
      "type": "string",
      "description": "Search query."
    }
  },
  "output": {}
}
```

`input` 是参数名到参数定义的直接映射，不再包裹 `type/properties`。`output` 保存来源返回字段映射或其他合法 JSON 值；来源未声明返回结构时写 `{}`。Python 提取器可额外保存 `ori_input` 和 `ori_description` 以保留原始签名及文档。

### 7.3 `class` 工具

Python 类使用 `type: "class"`、非空 `module`，并通过 `function` 数组保存类方法：

```json
{
  "name": "AbstractStructureFilter",
  "type": "class",
  "module": "pymatgen.alchemy.filters",
  "description": "Base filter for structures.",
  "input": "MSONable, abc.ABC",
  "function": [
    {
      "name": "test",
      "description": "Test whether a structure passes.",
      "input": {
        "structure": {
          "type": "Structure"
        }
      },
      "output": {
        "type": "bool"
      }
    }
  ]
}
```

类方法固定包含 `name/description/input/output`，并可带 `ori_input/ori_description`。

### 7.4 与正式工具契约的区别

种子参考工具保存来源能力线索，不直接套用 [tool.schema.json](tool.schema.json)：

| 项目 | 种子参考工具 | 正式公开工具 |
| --- | --- | --- |
| 名称 | 保留来源命名及可能的重复声明 | 必须符合正式工具命名和唯一性规则 |
| 输入输出 | 来源参数/返回定义的直接映射，可不完整 | 完整 JSON Schema 与运行协议 |
| 实现 | 不要求可执行 | 必须提供并验证实现 |
| 保证 | 不保证状态、回滚或确定性 | 必须满足正式工具契约 |

## 8. `init_ref_tasks`

来源提供任务时，每项包含：

```json
{
  "description": "Find and compare relevant records.",
  "input": {"query": "example"},
  "output": {"summary": "expected result"},
  "solution_path": [
    "Search the records",
    {"tool_name": "compare_records", "arguments": {"record_ids": ["a", "b"]}}
  ]
}
```

这些字段保存来源证据，不是最终任务 Prompt、标准答案或验证器。来源未提供任务时使用空数组，不推测调用参数或伪造答案。

## 9. `others` 与命名规则

`others` 是开放对象，其一级自定义 key 使用小写 `snake_case`。v1.1 强制包含：

```json
"tool_count": 1
```

`tool_count` 是非负整数，必须等于同条种子的 `init_ref_tools` 数量。JSON Schema 无法表达这一跨字段等式，因此生成器或 Validator 必须额外检查。

Smithery 产物还可包含：

```text
source_metadata / data_directions / organization_status
```

嵌套的来源原始载荷可保留原 key；项目新建字段使用 Python 命名法。`iconUrl`、缓存和临时错误不属于核心字段。`others` 不能覆盖 `global_id`、`basic_info.url/name/version` 的含义。

## 10. JSON Schema 之外的校验

机器 Schema 负责字段存在性、基本类型、固定层级和对象封闭性。以下关系必须由生成器或 Validator 补充检查：

```text
global_id 等于 source、规范化 name 和 index 的组合
global_id 在整个集合中唯一
同一 source 快照中的 index 唯一
每个 url 均能回溯到来源记录，且不含秘密信息
同一环境内参考工具重名需审计，但不得在种子层静默删除来源声明
others.tool_count 等于 init_ref_tools 的长度
正式数据不含中文注释 key、".."、"..." 等说明性占位
```

验证当前 Smithery 产物：

```powershell
python -c "import json; from pathlib import Path; from jsonschema import Draft202012Validator, FormatChecker; s=json.loads(Path('schemas/validation/env_seeds.schema.json').read_text(encoding='utf-8')); d=json.loads(Path('seed_gen/data/smithery_1000_v1_0902.json').read_text(encoding='utf-8')); errors=list(Draft202012Validator(s, format_checker=FormatChecker()).iter_errors(d)); assert not errors, errors[:3]; assert all(x['others']['tool_count']==len(x['init_ref_tools']) for x in d); print(len(d))"
```

当前产物预期输出 `975`。该检查只验证环境种子，不代表环境资源、工具实现或任务执行已经通过验收。

## 11. v1.1 生成检查清单

```text
1. 文件是 UTF-8 JSON 数组，且至少包含一条种子。
2. 每条种子包含六个固定顶层字段，schema_version == "1.1"。
3. global_id 可重算、格式正确且在集合中唯一。
4. basic_info 包含 source/url/name/version/index，url 是非空去重数组。
5. description 非空，domain 是连续的三级结构。
6. 无参考工具或任务时写空数组。
7. 参考工具包含 name/type/module/description/input；function 还包含 output。
8. MCP 工具使用 type=function、module=null，参数定义放入 input/output。
9. others.tool_count 是非负整数且等于 init_ref_tools 长度。
10. 参考工具和任务经过生成与验证后才进入正式产物。
```
