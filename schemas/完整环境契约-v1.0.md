# Agent-World Mini 完整环境契约 v1.0

结构示例见 [complete_environment.schema.json](complete_environment.schema.json)；机器校验规则见
[validation/complete_environment.schema.json](validation/complete_environment.schema.json)。校验规则引用
`validation/environment.schema.json` 和 `validation/tool.schema.json`。

## 1. 完整环境是什么

完整环境是环境生成阶段和工具生成阶段合并后的最终产物，也是任务生成、Runtime 执行和环境验证共同使用的权威描述：

```text
不带工具环境：环境信息 + resources[] + rules[]
工具集合：tools[]
完整环境：环境信息 + resources[] + rules[] + tools[]
```

完整环境 JSON 只允许以下七个顶层字段：

```text
schema_version / environment_id / name / description / resources / rules / tools
```

根对象禁止额外字段。种子、任务、验证报告、统计报告和 Runtime 配置都不是完整环境 JSON 的顶层字段。

## 2. 环境包目录

一个可执行环境包固定按以下方式组织：

```text
<environment_package>/
├── environment.json
└── workspace/
    └── resources[].path 对应的实际文件和目录
```

约定如下：

1. `environment.json` 必须通过 `validation/complete_environment.schema.json` 验证；外层 `complete_environment.schema.json` 是结构示例。
2. `resources[].path` 始终相对于 `workspace/`，不是相对于进程当前目录，也不是绝对路径。
3. `file` 资源声明的文件必须存在。
4. `file_collection` 的 glob 初始化时必须至少匹配一个文件。
5. `directory` 资源声明的目录必须存在；`output` 目录可以为空，也可以包含环境初始状态中的历史产物。
6. Runtime 的重置、临时目录和进程隔离属于统一运行框架，不写进每个环境 JSON。

环境集合可以额外包含 `index.json`、`validation.json`、统计报告和 `provenance/` 来源目录。这些是包级旁路文件，不属于单个环境对象。Schema 和契约只保存在仓库中央 `schemas/`，不复制到生成环境集合中。

## 3. 顶层字段

| 字段 | 类型 | 必需 | 精确定义 | 主要消费者 |
| --- | --- | --- | --- | --- |
| `schema_version` | string | 是 | 完整环境协议版本；v1.0 固定为 `"1.0"` | Loader、Validator |
| `environment_id` | string | 是 | 环境稳定唯一 ID，使用小写 `snake_case` | 全流水线 |
| `name` | string | 是 | 人工审核和索引使用的简短名称 | 人工审核、TaskGen |
| `description` | string | 是 | 现实业务场景、数据范围和环境用途 | ToolGen、TaskGen |
| `resources` | array | 是 | 工作区中实际存在的文件、文件集合和目录 | Loader、ToolGen、TaskGen |
| `rules` | array | 是 | 资源内部或资源之间无法只靠文件格式表达的业务约束 | ToolGen、TaskGen、Validator |
| `tools` | array | 是 | 至少一个完整工具定义，包含公开接口和内部代码 | Agent、Runtime、Validator |

`resources` 和 `rules` 的字段定义以 [环境契约 v1.0](环境契约-v1.0.md) 为准；每个 `tools[]` 元素以 [工具契约 v1.0](工具契约-v1.0.md) 为准。完整环境契约不复制或改变两者的内部字段含义。

## 4. `resources[]` 在完整环境中的作用

资源不是为了把所有文件强行抽象成实体，而是为后续阶段提供稳定的逻辑入口。

| `data_type` | 在完整流水线中的作用 |
| --- | --- |
| `raw` | 保存原始证据和业务输入；工具可以读取，但只有 `writable=true` 时才允许修改 |
| `entity` | 暴露可稳定查询、关联和更新的业务对象；`entity_schema` 告诉 ToolGen 和 TaskGen 每种记录有哪些字段、字段含义和可验证约束 |
| `derived` | 保存环境初始化阶段已经计算好的索引、基线、统计或控制规则 |
| `output` | 限定任务执行期允许产生文件的范围；固定为 `writable=true` |

`storage_type` 与 `data_type` 相互独立：

```text
storage_type：资源在磁盘上是一个文件、一组文件还是目录
data_type：资源在业务流程中是原始、实体、派生还是输出
```

`entity_schema` 只描述后续需要识别的实体类型及其字段定义，不复制全部数据、不规定 CRUD 工具，也不要求所有资源都实体化。具体结构以环境契约的 `description/fields` 定义为准。

## 5. `tools[]` 在完整环境中的作用

每个工具固定包含：

```text
name / description / inputSchema / outputSchema / internal
```

其中：

| 字段 | Agent 可见 | 用途 |
| --- | --- | --- |
| `name` | 是 | 稳定工具名和调用路由键 |
| `description` | 是 | 告诉 Agent 何时调用、限制和主要副作用 |
| `inputSchema` | 是 | 验证 Agent 传入的 `arguments` |
| `outputSchema` | 是 | 定义成功 `data` 和失败 `error` 的完整返回结构 |
| `internal.code` | 否 | Runtime 执行的 Python 实现 |

`internal.code` 必须定义：

```python
def run(arguments: dict, context) -> dict:
    ...
```

v1.0 唯一保证的 Runtime 上下文能力是：

```python
context.workspace_root: pathlib.Path
```

工具通过 `context.workspace_root / <relative_path>` 访问资源。工具不得依赖进程当前目录，不得读写工作区外路径，也不得通过 `..` 或绝对路径绕过资源边界。

## 6. Agent、TaskGen、Runtime 分别拿什么

### 6.1 Agent 和 TaskGen 可见视图

Agent 和 TaskGen 可以获得：

```text
schema_version / environment_id / name / description / resources / rules
tools[].name / description / inputSchema / outputSchema
```

必须移除：

```text
tools[].internal
```

标准投影为：

```python
public_environment = {
    **{key: value for key, value in environment.items() if key != "tools"},
    "tools": [
        {
            "name": tool["name"],
            "description": tool["description"],
            "inputSchema": tool["inputSchema"],
            "outputSchema": tool["outputSchema"],
        }
        for tool in environment["tools"]
    ],
}
```

TaskGen 根据资源、规则和公开工具接口设计可执行任务；它不需要看到工具代码。

### 6.2 Runtime 和 Validator 视图

Runtime 和 Validator 使用完整对象，包括 `internal.code`。Runtime 负责：

1. 为一次 rollout 准备独立 `workspace_root`。
2. 按工具名定位工具定义。
3. 用 `inputSchema` 验证 `arguments`。
4. 编译并调用 `internal.code` 中的 `run(arguments, context)`。
5. 用 `outputSchema` 验证返回对象。
6. 在 rollout 结束后销毁临时工作区，保证下一次从同一初始状态开始。

## 7. 返回和失败契约

所有工具统一使用互斥的两个返回分支：

```json
{"success": true, "data": {}}
```

```json
{
  "success": false,
  "error": {
    "code": "not_found",
    "path": "$.resource_id",
    "message": "Resource not found.",
    "retryable": false
  }
}
```

业务失败必须返回 `success=false`，不能通过抛出普通异常表达。实现错误、环境损坏或 Runtime 故障可以抛出异常并由 Runtime 记录为执行失败。

## 8. 完整环境必须满足的跨字段规则

JSON Schema 之外，Validator 还必须检查：

1. `resources[].resource_id` 在环境内唯一。
2. `tools[].name` 在环境内唯一。
3. `source_resources[]` 只能引用已经声明的 `resource_id`。
4. `rules[].resources[]` 只能引用已经声明的 `resource_id`。
5. 所有非输出资源和目录在初始化工作区中真实存在。
6. `file_collection` 至少匹配一个真实文件。
7. 每段 `internal.code` 可以编译，并提供可调用的 `run`。
8. 代表性调用同时通过 `inputSchema` 和 `outputSchema`。
9. 工具只能修改 `writable=true` 的资源范围。
10. 工具失败时不得留下部分状态；批量状态变更必须具备原子性。

## 9. 不进入完整环境 JSON 的内容

以下内容均使用旁路文件或 Runtime 固定约定，不增加顶层字段，也不进入 `resources[]`：

| 内容 | 保存位置 |
| --- | --- |
| MCP Server 种子、工具目录和生成来源 | 包级 `provenance/`；它们是生成依据，不是 Agent 操作的业务资源 |
| 工作区绝对路径 | Runtime 注入的 `context.workspace_root` |
| 重置和隔离方式 | Runtime 固定实现 |
| 工具烟雾测试结果 | `validation.json` |
| 环境统计 | `environment_statistics.json` 或审阅报告 |
| 任务、参考轨迹和评分 | 后续任务协议 |
| Agent rollout 过程状态 | Runtime 临时状态和日志 |

只有当某个来源文件本身就是任务场景中的业务输入，并且工具会在任务中读取或处理它，才可以把它声明为 `raw` 资源。例如需要解析的 OFX、JUnit、SARIF 或音频文件可以是业务输入；描述这些文件从哪里下载、使用什么许可证的 provenance 元数据不能是业务资源。

这样可以保证最终协议只保存环境、资源边界、业务规则和可执行工具，不把生成过程或运行框架细节重复写入每个环境。

## 10. 最小合法结构

```json
{
  "schema_version": "1.0",
  "environment_id": "example_environment_001",
  "name": "示例环境",
  "description": "包含真实工作区资源和可执行工具的示例环境。",
  "resources": [
    {
      "resource_id": "input_records",
      "name": "输入记录",
      "description": "环境初始化时已经存在的原始 JSON 记录。",
      "data_type": "raw",
      "storage_type": "file",
      "path": "raw/input_records.json",
      "format": "json",
      "writable": false
    },
    {
      "resource_id": "reports",
      "name": "报告目录",
      "description": "工具生成报告的输出目录。",
      "data_type": "output",
      "storage_type": "directory",
      "path": "reports/",
      "format": "directory",
      "writable": true
    }
  ],
  "rules": [],
  "tools": [
    {
      "name": "count_input_records",
      "description": "统计输入记录数量，不修改工作区。",
      "inputSchema": {
        "type": "object",
        "properties": {},
        "required": [],
        "additionalProperties": false
      },
      "outputSchema": {
        "oneOf": [
          {
            "type": "object",
            "properties": {
              "success": {"type": "boolean", "const": true},
              "data": {
                "type": "object",
                "properties": {"count": {"type": "integer", "minimum": 0}},
                "required": ["count"],
                "additionalProperties": false
              }
            },
            "required": ["success", "data"],
            "additionalProperties": false
          },
          {
            "type": "object",
            "properties": {
              "success": {"type": "boolean", "const": false},
              "error": {
                "type": "object",
                "properties": {
                  "code": {"type": "string", "enum": ["internal_error"]},
                  "path": {"type": "string"},
                  "message": {"type": "string", "minLength": 1},
                  "retryable": {"type": "boolean"}
                },
                "required": ["code", "path", "message", "retryable"],
                "additionalProperties": false
              }
            },
            "required": ["success", "error"],
            "additionalProperties": false
          }
        ]
      },
      "internal": {
        "code": "def run(arguments, context):\n    import json\n    path = context.workspace_root / 'raw' / 'input_records.json'\n    records = json.loads(path.read_text(encoding='utf-8'))\n    return {'success': True, 'data': {'count': len(records)}}\n"
      }
    }
  ]
}
```
