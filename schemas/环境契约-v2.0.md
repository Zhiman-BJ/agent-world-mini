# Agent-World Mini 环境契约 v2.0

本文定义当前 DataGen v2 管线使用的环境数据逻辑模型和物理存储。配套机器 Schema 为
`schemas/validation/environment-v2.schema.json`，运行入口会在发布前按该 Schema 独立校验。
v1.0 仅作为历史兼容协议保留，不适用于 v2 管线新生成的环境。

## 1. 协议解决什么问题

一个离线环境可能同时包含两类数据：

1. 适合查询、筛选、统计和关联的结构化记录；
2. 必须保留原始字节或目录结构，由专业工具读取、验证、转换或修改的文件材料。

v2.0 按后续访问方式组织数据：

```text
environment.json
├── record_sets[]          可按字段访问的记录集合
├── relationships[]       Record Set 之间已验证的关系
└── filesystem_scopes[]   工具可访问的文件或目录范围
```

三者分别回答：

| 部分 | 回答的问题 |
| --- | --- |
| `record_sets` | 有哪些记录、每条记录有哪些字段 |
| `relationships` | 哪些顶层字段可以可靠地跨表关联 |
| `filesystem_scopes` | 哪些文件或目录可以交给文件工具处理 |

本协议主要供 DataGen、Validator、ToolGen 和 Runtime 使用。交互 Agent 不直接读取
`environment.json`，系统会根据环境和工具定义生成更简短的 Agent 上下文。

## 2. 环境包

### 2.1 物理布局

```text
<environment_root>/
├── environment.json
├── state/
│   ├── records.sqlite
│   └── filesystem_scopes/
│       ├── <scope_id_a>/
│       └── <scope_id_b>/
└── provenance/
    ├── raw/
    ├── source_inventory.json
    ├── transformations/
    └── profiles/
```

| 路径 | 用途 | 是否为任务可用状态 |
| --- | --- | --- |
| `environment.json` | 唯一机器契约 | 是 |
| `state/records.sqlite` | 所有 Record Set 的基线记录 | 是 |
| `state/filesystem_scopes/<scope_id>/` | 文件工具可访问的基线材料 | 是 |
| `provenance/` | 来源、Raw、转换和质量证据 | 否 |

存在性要求：

1. `record_sets` 非空时必须存在 `state/records.sqlite`；
2. 每个 `scope_id` 必须对应一个同名物理目录；
3. 没有 Record Set 或 Filesystem Scope 时，可以省略对应物理存储；
4. Loader 不得把 `provenance` 暴露为业务数据；
5. 任务修改发生在 Runtime 创建的隔离副本中，不写回基线。

### 2.2 JSON 通用规则

`environment.json` 使用 UTF-8 且不带 BOM，并满足标准 JSON 语法。禁止注释、尾随逗号、
重复对象键、`NaN` 和 `Infinity`。

除 `fields` 和 `properties` 这种“名称到定义的映射”外，协议中的所有对象都是闭合对象：
只能包含对应章节列出的字段。需要增加契约字段时必须升级协议，不能由单个环境私自扩展。

## 3. 顶层对象

### 3.1 字段

顶层对象固定包含以下字段：

| 字段 | 类型 | 要求 | 用途 |
| --- | --- | --- | --- |
| `schema_version` | string | 必填，固定为 `2.0` | 选择协议和 Validator |
| `environment_id` | string | 必填，全局唯一 | 稳定标识环境 |
| `name` | string | 必填，1 至 120 字符 | 人类可读名称 |
| `description` | string | 必填，非空 | 说明场景、数据范围和离线边界 |
| `record_sets` | array | 必填，可为空 | 声明结构化记录 |
| `relationships` | array | 必填，可为空 | 声明已验证的记录关系 |
| `filesystem_scopes` | array | 必填，可为空 | 声明文件访问范围 |

`record_sets` 和 `filesystem_scopes` 不能同时为空。`relationships` 非空时，
`record_sets` 必须非空。

所有资源和需求描述只陈述稳定语义、用途与边界，不重复当前文件数、记录数或成员数。数量由画像
从 `state` 实际计算，避免补采或重建后出现两份互相矛盾的事实。

### 3.2 ID 规则

| ID | 格式 | 唯一范围 |
| --- | --- | --- |
| `environment_id` | `^[a-z][a-z0-9_]{2,127}$` | 发布系统 |
| `record_set_id` | `^[a-z][a-z0-9_]{1,62}$` | 当前环境 |
| `relationship_id` | `^[a-z][a-z0-9_]{2,127}$` | 当前环境 |
| `scope_id` | `^[a-z][a-z0-9_]{1,62}$` | 当前环境 |

`record_set_id` 同时作为 SQLite 表名，`scope_id` 同时作为 Scope 目录名。两者不得使用
`sqlite_` 前缀，也不得使用 `raw`、`derived`、`output`、`temp` 或 `misc`
这类阶段名和兜底名。

## 4. Record Set

### 4.1 字段

每个 Record Set 只能包含以下字段：

| 字段 | 类型 | 要求 | 用途 |
| --- | --- | --- | --- |
| `record_set_id` | string | 必填，环境内唯一 | 逻辑集合 ID 和 SQLite 表名 |
| `name` | string | 必填，非空 | 显示名称 |
| `description` | string | 必填，非空 | 首先说明一条记录代表什么 |
| `access` | enum | 必填 | 声明任务级可变性 |
| `key_fields` | string[] | 必填，可为空 | 记录的稳定组合键 |
| `fields` | object | 必填，至少一个字段 | 字段名到字段定义的映射 |

### 4.2 `access`

| 值 | 含义 |
| --- | --- |
| `read_only` | 工具只能读取该 Record Set |
| `copy_on_write` | 工具可修改 Runtime 创建的任务副本 |

环境包中的 `records.sqlite` 始终是只读基线。`copy_on_write` 不表示 Agent 可以直接访问
SQLite 文件。

### 4.3 `key_fields`

`key_fields` 是共同唯一标识一条记录的顶层字段数组。

规则：

1. 每个键必须存在于当前 `fields`；
2. 只能使用 `nullable=false` 的顶层标量字段；
3. 非空键组合必须在表中唯一；
4. 复合键按数组顺序解释，字段不能重复；
5. 没有可靠键时必须使用空数组 `[]`。

SQLite 的内部 `rowid` 不属于业务字段。DataGen 可以生成可复算的稳定 ID，但不能随机伪造
业务标识；生成方法保存在 provenance。

### 4.4 `fields`

`fields` 是动态映射：

```text
字段名 -> Field Definition
```

字段名必须匹配 `^[a-z][a-z0-9_]{0,62}$`，并与 SQLite 列名完全一致。每个顶层字段
在 SQLite 表中对应一列。

## 5. Field Definition

本节同时定义顶层字段和嵌套值。二者使用相同的基础语法，但只有顶层字段可以声明文件引用。

### 5.1 公共字段

每个 Field Definition 都必须包含：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `type` | enum | 值的逻辑类型 |
| `description` | string | 当前值在业务中的准确含义 |
| `nullable` | boolean | 是否允许该值为 `null` |

`type` 允许：

```text
string
integer
number
boolean
object
array
```

`nullable` 在两个位置的含义不同：

| 位置 | `nullable=true` 的含义 |
| --- | --- |
| 顶层字段 | SQLite 列允许 SQL `NULL` |
| `properties` 或 `items` 中 | 对应 JSON 值或数组元素允许 JSON `null` |

空字符串、空数组和空对象不能代替 `null`。

### 5.2 各类型允许的参数

Field Definition 是闭合对象。除三个公共字段外，只能按类型使用下表参数：

| `type` | 可选或附加参数 |
| --- | --- |
| `string` | `format`、`pattern`、`minLength`、`maxLength`、`enum`、`const` |
| `integer` | `minimum`、`maximum`、`exclusiveMinimum`、`exclusiveMaximum`、`multipleOf`、`enum`、`const` |
| `number` | 与 `integer` 相同 |
| `boolean` | `const` |
| `object` | 必须增加 `properties`、`required`、`additionalProperties` |
| `array` | 必须增加 `items`；可增加 `minItems`、`maxItems`、`uniqueItems` |

顶层 `string` 或“元素为 string 的顶层 `array`”还可以增加 `reference`，见第 5.7 节。
其他组合均为协议错误。

### 5.3 标量类型

#### String

`format` 允许：

```text
date / date-time / time / duration
uri / uuid / email / hostname / ipv4 / ipv6
```

`pattern` 使用 ECMA-262 正则；`minLength` 和 `maxLength` 按 Unicode 字符数计算。

#### Integer 与 Number

`integer` 表示整数，`number` 表示允许浮点表示的数值。货币或高精度十进制应使用整数最小
单位，或者使用具有格式约束的字符串。

#### Boolean

三态值不能写成真假混合字符串。应使用字符串枚举，或者用 `nullable=true` 并明确 `null`
的业务含义。

#### Enum 与 Const

`enum` 必须非空、无重复且成员类型与 `type` 一致。`const` 必须与 `type` 一致。
二者不能同时出现，也不能仅因当前样本只出现一个值就声明 `const`。

### 5.4 Object

`object` 只表示“由当前记录拥有、无需独立查询和寻址”的值对象。

```json
{
  "type": "object",
  "description": "图纸页面的物理尺寸。",
  "nullable": true,
  "properties": {
    "width_mm": {
      "type": "number",
      "description": "页面宽度，单位为毫米。",
      "nullable": false,
      "exclusiveMinimum": 0
    },
    "height_mm": {
      "type": "number",
      "description": "页面高度，单位为毫米。",
      "nullable": false,
      "exclusiveMinimum": 0
    },
    "standard_name": {
      "type": "string",
      "description": "来源声明的纸张规格名称。",
      "nullable": true
    }
  },
  "required": ["width_mm", "height_mm"],
  "additionalProperties": false
}
```

参数含义：

| 参数 | 类型 | 要求 |
| --- | --- | --- |
| `properties` | object | 属性名到嵌套 Field Definition 的映射，至少一个属性 |
| `required` | string[] | 必须出现在对象中的属性名，可为空，不得重复 |
| `additionalProperties` | boolean | 必须出现且固定为 `false` |

`required` 和嵌套字段的 `nullable` 是两个独立约束：

| 声明 | 结果 |
| --- | --- |
| 在 `required` 中，`nullable=false` | 键必须存在，值不能为 `null` |
| 在 `required` 中，`nullable=true` | 键必须存在，值可以为 `null` |
| 不在 `required` 中，`nullable=false` | 键可以缺失；存在时不能为 `null` |
| 不在 `required` 中，`nullable=true` | 键可以缺失；存在时可以为 `null` |

顶层 Object 整体为 SQL `NULL` 时，不再检查内部 `required`。Object 非空时才检查其属性。

### 5.5 Array

`array` 表示当前记录拥有的有序或无序多值属性。

```json
{
  "type": "array",
  "description": "图纸来源提供的业务标签。",
  "nullable": false,
  "items": {
    "type": "string",
    "description": "一个业务标签。",
    "nullable": false,
    "minLength": 1
  },
  "minItems": 0,
  "uniqueItems": true
}
```

参数含义：

| 参数 | 类型 | 要求 |
| --- | --- | --- |
| `items` | Field Definition | 必填，定义每个数组元素 |
| `minItems` | integer | 可选，大于等于 0 |
| `maxItems` | integer | 可选，大于等于 `minItems` |
| `uniqueItems` | boolean | 可选，是否禁止重复元素 |

数组本身的 `nullable` 不控制元素。是否允许 `null` 元素由 `items.nullable` 决定：

```json
{
  "type": "array",
  "description": "允许缺测值的三个测量结果。",
  "nullable": false,
  "items": {
    "type": "number",
    "description": "一次测量结果；null 表示该次测量缺失。",
    "nullable": true
  },
  "minItems": 3,
  "maxItems": 3
}
```

需要跨记录关联、独立筛选或携带自身业务字段的多个对象，不应藏在数组中，应拆成独立
Record Set 或关联 Record Set。

### 5.6 嵌套边界

Object 和 Array 可以组合，但容器嵌套深度最多为 2：

```text
顶层 scalar                         深度 0
顶层 object 或 array                容器深度 1
其 property/item 再含 object/array  容器深度 2
深度 2 内只能继续声明标量值          不允许深度 3
```

因此以下形式合法：

```text
object -> scalar
object -> array -> scalar
array  -> object -> scalar
array  -> array  -> scalar
```

以下形式不合法：

```text
object -> object -> array
array  -> object -> object
在嵌套对象中复制另一条 Record
用 ID 数组代替 Record 关系
```

嵌套属性：

1. 不产生 SQLite 独立列；
2. 不能进入 `key_fields`；
3. 不能作为 `relationships` 端点；
4. 不能声明文件 `reference`；
5. 不能被其他 Record 单独引用。

只要嵌套值需要上述能力，就应拆成独立 Record Set。Object 和 Array 列统一以 JSON 文本保存，
Loader 负责解码。

### 5.7 文件路径 `reference`

`reference` 只把顶层 Record 字段连接到一个 Filesystem Scope：

```json
{
  "type": "string",
  "description": "对应 DXF 图纸在 drawing_files Scope 中的相对路径。",
  "nullable": false,
  "reference": {
    "kind": "filesystem_path",
    "scope_id": "drawing_files",
    "target": "file"
  }
}
```

`reference` 固定包含：

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `kind` | string | 固定为 `filesystem_path` |
| `scope_id` | string | 必须引用存在的 Scope |
| `target` | enum | `file` 或 `directory` |

适用形式：

1. 顶层 `type=string`：一个路径；
2. 顶层 `type=array` 且 `items.type=string`：多个路径。

路径值相对于 Scope 根，使用 POSIX 分隔符，禁止绝对路径、URL、空路径以及 `.`、`..`
路径段。路径必须存在，解析符号链接后不能逃逸 Scope，并符合 `target` 类型。

多条 Record 可以引用同一路径。文件路径不要求唯一，也不需要给每个文件分配 `file_id`。

## 6. Relationships

### 6.1 字段

每条关系只能包含以下字段：

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `relationship_id` | string | 必填，环境内唯一 |
| `description` | string | 必填，说明可判断真假的业务关系 |
| `from` | endpoint | 必填，来源端 |
| `to` | endpoint | 必填，目标端 |
| `cardinality` | enum | `many_to_one` 或 `one_to_one` |

端点固定包含 `record_set_id` 和非空的 `fields` 数组。端点字段只能是顶层标量字段。

### 6.2 完整性规则

1. 两端字段数量相同且对应类型兼容；
2. `to.fields` 的组合值唯一且非空；
3. 所有非空来源组合都能在目标表中找到；
4. 复合来源要么整组为 `NULL`，要么整组非空；
5. `one_to_one` 还要求非空来源组合唯一；
6. 自引用和业务关系环合法。

一对多用反向的 `many_to_one` 表达。多对多必须增加关联 Record Set，并分别声明两条
`many_to_one` 关系，不能使用 ID 数组替代。

## 7. Filesystem Scope

### 7.1 字段

每个 Scope 只能包含以下字段：

| 字段 | 类型 | 要求 | 用途 |
| --- | --- | --- | --- |
| `scope_id` | string | 必填，环境内唯一 | 逻辑范围和物理目录名 |
| `name` | string | 必填，非空 | 显示名称 |
| `description` | string | 必填，非空 | 说明材料、组织方式和文件处理用途 |
| `access` | enum | 必填 | `read_only` 或 `copy_on_write` |
| `structure` | object | 必填 | 描述工具可以依赖的稳定目录形状 |

一个 Scope 对应：

```text
state/filesystem_scopes/<scope_id>/
```

### 7.2 Structure 节点

允许四种 `kind`：

| kind | 表示 | `path` | 必须字段 | 禁止字段 |
| --- | --- | --- | --- | --- |
| `file` | 一个确定文件 | 确定相对路径 | `format` | `layout` |
| `file_collection` | 一组同格式文件 | 含 glob | `format` | `layout` |
| `directory` | 一个确定目录 | 确定路径或顶层 `.` | `layout` | `format`、`content_validation` |
| `directory_collection` | 多个同结构目录 | 含 glob | `layout` | `format`、`content_validation` |

顶层 `structure` 只包含 `kind`、`path` 及该 kind 所需字段。嵌套 `layout` 节点还必须
包含：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `description` | string | 该分支存放什么 |
| `required` | boolean | 当前父目录中是否必须存在或至少匹配一项 |

`layout` 至少包含一个节点。`required=false` 的节点可以不存在，但存在时仍必须满足格式和
子布局。

### 7.3 四种常见形态

| 场景 | 声明方式 |
| --- | --- |
| 单个 PDF | `kind=file`、`path=standard.pdf`、`format=pdf` |
| 一批 XML | `kind=file_collection`、`path=**/*.xml`、`format=xml` |
| 一个源码工程 | `kind=directory`、通常 `path=.`，用 `layout` 描述稳定分支 |
| 多个同构工程 | `kind=directory_collection`、`path=*`，用一份 `layout` 作为成员模板 |

`directory_collection.layout` 对所有成员只声明一次。成员结构本质不同时，应拆成多个 Scope。

### 7.4 路径和布局规则

所有结构路径：

1. 使用 POSIX 分隔符；
2. 相对于当前节点根；
3. 禁止绝对路径、空字符串和 `..`；
4. 只有 collection kind 允许 glob；
5. 只有顶层目录可以用 `.` 表示 Scope 根；
6. 匹配区分大小写。

`file_collection` 只从普通文件中匹配，`directory_collection` 只从目录中匹配。
Collection 初始化时至少匹配一项。

`layout` 不是逐文件索引，同类文件应使用 `file_collection` 的 glob 一次描述；但它对最终
Scope 中的普通文件必须是穷尽的。每个实际文件都必须被某个 `file` 或 `file_collection`
节点覆盖。这样工具看到的目录说明与实际可访问内容一致，不会出现名为“XML 样本”的 Scope
暗中混入未说明的媒体或文档。无需向任务暴露的文件应在物化时排除，而不是留作未声明成员。

顶层 `file` Scope 根中只能包含声明文件；顶层 `file_collection` Scope 中不能混入未被
模式覆盖的普通文件。任何 Scope 都不得包含 provenance、缓存、任务输出或环境外状态。

### 7.5 `format`

`format` 使用小写稳定名称，不带前导点，也不写 Python 包名，例如：

```text
json / yaml / csv / parquet / xml
pdf / docx / markdown / text
geojson / geopackage / shapefile
dxf / dwg / gdsii / lef / def
png / jpeg / tiff / svg
wav / mp3 / mp4
python / javascript / source_text
```

Validator 应结合扩展名、文件签名或轻量解析检查格式，不能只检查扩展名。

文件节点可以增加 `content_validation`：

| 值 | 含义 |
| --- | --- |
| `strict` | 默认值；文件必须通过该格式的轻量解析 |
| `allow_invalid` | 文件属于该格式家族，但初始内容允许解析失败，用于诊断、修复或坏样本比较 |

`allow_invalid` 不表示忽略格式：路径仍须匹配、扩展名仍须符合 `format`，画像还必须报告实际
解析失败的文件。若 Record 表示这些文件，应该用 `parse_status`、`validation_status` 等业务字段
明确记录初始状态。不能用它掩盖下载错误、HTML 错页或任意二进制内容。

## 8. SQLite 物化

`state/records.sqlite` 是 SQLite 3 数据库。每个 Record Set 对应一张同名普通表。

### 8.1 类型映射

| 逻辑类型 | SQLite 类型 | Loader 返回 |
| --- | --- | --- |
| `string` | `TEXT` | string |
| `integer` | `INTEGER` | integer |
| `number` | `REAL` | number |
| `boolean` | `INTEGER`，仅 `0/1` | boolean |
| `object` | `TEXT`，规范 JSON Object | object |
| `array` | `TEXT`，规范 JSON Array | array |

Record Set 禁止业务 BLOB 列。需要原始字节的数据必须进入 Filesystem Scope。

### 8.2 数据库要求

发布前必须满足：

1. `PRAGMA integrity_check` 返回 `ok`；
2. 所有 WAL 已 checkpoint，包中没有 `-wal` 或 `-shm` 文件；
3. 每个 Record Set 有一张同名表；
4. 表的业务列与 `fields` 完全一致；
5. 不存在未声明的业务表和列；
6. 值满足类型、约束和 `nullable`；
7. Object/Array 文本可解析并满足嵌套定义；
8. `key_fields` 非空时组合值唯一；
9. 行顺序没有业务含义，工具必须显式排序。

## 10. Validator

Validator 至少执行以下检查：

### 10.1 契约

```text
必填字段存在且没有未知字段
ID、字段名和枚举合法
Field Definition 的参数与 type 匹配
Object/Array 嵌套不超过两层
所有引用的 Record Set、字段和 Scope 存在
```

### 10.2 记录

```text
SQLite 完整性、表和列一致
标量类型、format、范围、enum、const 和 nullable
Object/Array JSON 及其嵌套字段
key_fields 唯一
关系目标唯一、来源闭合、基数成立，并且至少存在一条实际命中
```

### 10.3 文件

```text
Scope 根存在且彼此隔离
路径和符号链接不越界
required 节点存在
collection 至少匹配一项
文件格式与声明一致
Record 文件引用存在、目标类型正确，并且至少存在一个实际解析路径
```

### 10.4 隔离

```text
environment.json 不引用 provenance
state 不包含 Raw、画像、缓存或任务输出
records.sqlite 不属于任何 Filesystem Scope
任务修改不写回基线
```

## 11. 数据边界

### 11.1 进入 Record Set

需要按字段查询、筛选、排序、统计、Join 或结构化修改的数据进入 Record Set。来源可以是
CSV、JSON、JSONL、XLSX、HTML 表格或 API；来源格式不决定最终表示。

### 11.2 进入 Filesystem Scope

只有工具必须直接处理路径、原始字节或目录结构时才进入 Scope，例如 XML、PDF、DOCX、CAD、
地理文件、媒体文件或源码工程。

只用于采集和转换的 API JSON、CSV、网页、压缩包和画像留在 provenance。压缩包只是下载载体时，
Scope 保存确定性解包后的目录；只有任务需要处理归档本身时才保存压缩包。

### 11.3 Record 与文件的连接

Record 可以引用一个文件、多个文件或一个目录；多条 Record 也可以共享同一路径。协议不建立
文件对象图，也不为每个文件强制生成记录。

同一来源同时具有结构化索引和文件本体时，provenance 必须声明哪一个是主事实、哪一个可重建。
任务中修改一侧不会自动同步另一侧，必须由显式的重新索引或导出工具完成。

## 12. Agent 可见性

`environment.json` 是 ToolGen、Validator 和 Runtime 的机器输入，不直接供交互 Agent 阅读。

系统可以确定性生成：

```text
environment.json + 只读统计
                 ↓
          environment.md
```

`environment.md` 是可选视图，不是新的事实源。ToolGen 完成后再组合环境可读视图、工具说明和
Runtime 规则，生成 Agent 实际看到的 `agent_context.md`。

Agent 通常只看到逻辑 Record Set、工具、任务文本和 Scope 相对路径，不看到：

```text
state/records.sqlite
Scope 的真实物理根
provenance
DataGen 内部目录
```

## 13. v1.0 迁移摘要

| v1.0 内容 | v2.0 去向 |
| --- | --- |
| Raw API、网页、下载文件 | `provenance/raw/` |
| Entity JSON/JSONL/CSV | 规范化后写入 Record Set |
| 需要查询的 Derived 数据 | Record Set |
| 需要工具处理的 XML、CAD、媒体或工程目录 | Filesystem Scope |
| 只用于转换的 Derived 文件 | provenance |
| Output | Runtime 任务状态，不进入环境基线 |

迁移不能按旧 Resource 一对一机械转换。必须先判断最终数据是按记录访问、按文件访问，还是仅为
采集证据。
