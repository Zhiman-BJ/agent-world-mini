## 已确认的业务与数据限制

### 校准环境：有记录不等于 Agent 能发现记录

正式工具普遍先要求项目/网络/关系 ID，缺少可从名称定位对象的列表或搜索入口。生成阶段曾猜测 ID；独立 Kimi 的 task1、task4 未能可靠找到对象，均未完成。不能因为 verifier 能读 SQLite，就认为只允许工具访问的 Agent 也能取得这些标识；task4 verifier 的这项归因不准确，但没有完成操作的失败事实成立。

task3 通过探索进行了实际操作，导出的文件存在且格式正确，原评测仍判为失败：最终回答缺少部分项目输入/配对审核及 IEEE 370 单端两种方案的质量比较。回答开头的半句现已定位为适配器丢失续写前缀：第 11 次 API 流先返回 584 字，再报服务端错误；SDK 保留前缀后重试，第 12 次正常续写 1233 字。适配器只取最后一条 assistant 消息，丢掉了前 584 字，并非上下文或输出长度截断。修复后应合并末尾连续无工具调用的 assistant 消息。已有执行不重做，从原 context 恢复全文后独立复验，原结果不覆盖。

原独立评测证据：`evaluation/20260918_023738_758785/results.json`，3 条结果均为 fail，基础设施错误为 0。修复后的 task3 全文复验：`evaluation/calibration_task3_answer_recovery/recovery.json`，结果为 **pass**，全部五项要求通过；答案从 1233 字恢复为 1817 字，工具操作没有重做。按修正后的证据，校准为 1/3 通过，不能继续把旧的 task3 失败当作最新结论，也不能把此次复验计为新增任务。

### 泛型 FEM：计算和渲染能力不完全对齐

task2、task3 的瞬态计算返回了数值，但对应响应图渲染提示缺少 `petsc4py`。根因不止缺包：瞬态工具只执行模型源码的部分定义，再用 SciPy 求解；渲染器执行完整源码，进入 SLEPc 路径，需要 PETSc/SLEPc，而且随后要求模型提供 `evolve/u_init/probe`，TiN 源码并没有这些接口。因此安装依赖仍不能使该组合成立。上游渲染验收只覆盖另一模型的 field 模式，没有覆盖 TiN 的 response_curve/animation。

本次不安装大套件掩盖契约问题、不更改科学计算语义。上游应准确声明并校验可渲染的模型/模式；若要支持 TiN 图件，应让渲染器直接消费瞬态工具返回的时间序列或场数据，而不是重跑不同默认参数的模型。task2 还发现稳态与瞬态模型的几何、导热率、网格设置不一致，不能当作同一模型的闭环验证。这些候选未被强行标为完成。

另外三个候选的明确阻断点：task1 网格生成器把空边界/子域写成数组，项目校验器却要求对象；task4 按 0–6 mA 计算后，渲染器重新执行原源码默认 7.4 mA 工况，输出图文件名不能证明工况正确；task5 校验和导出了加密 disk 网格，但瞬态模型仍自行生成矩形网格，二者没有真实连接。后两项虽被 Step 3 自报完成，Step 5 仍将其拒绝。

### 本征模：正例可执行不等于历史扫描可复现

候选比较发现部分保存扫描、设计参数与工艺层栈厚度不一致，重算曲线无法在相同配置下复现。另有版图截线求解返回高折射率基底模，不能直接当作所需芯层导模；求解成功不等于物理模式身份已证实。这些限制由实际轨迹保留，未用适配代码替工具补科学结论。

task4 曾被执行阶段标为完成，但导出的导模筛选表只保留了第三阶导模存在的三个宽度点，漏掉其他九点中的第一、第二阶导模，最终校验拒绝。这是生成 Agent 的筛选错误，不是运行时或上游缺包。

### 云仿真：数据来源不能被名称替换

重跑 task1 完成了工具操作，但将 Meep 原始文本与由同一 Meep 来源登记的测量比较，误称为 Tidy3D/Meep 跨求解器核对。Step 5 识别数据集来源后拒绝；没有把“算出了 RMSE”当作“完成跨来源验证”。task5 明确审计现有证据及缺口，独立 Kimi 和 verifier 均通过。
