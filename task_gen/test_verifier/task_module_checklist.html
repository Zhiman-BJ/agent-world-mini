六个困难任务：Verifier 模块拆分清单

目的：把“任务目标”拆成可独立评分的模块，同时把 verifier 能力拆开。静态只负责规则明确、直接重算或直接对照的工作；理解自由文字、提取事实和专业判断交给 Codex。

判断原则：“能写程序”不等于“应该写程序”。如果输入表达变化很大，先让 Codex 抽取成结构化事实；如果抽取后的规则固定，再用程序裁决。这样避免用脆弱正则替代理解。
阅读方式：先看每个任务的“任务抽象”：目标对象、输入形态、需要执行的动作、输出形态。它只抽取任务结构，不替换原文；原文和专业文件清单继续保留在下面。
通用形式说明：
  • SQLite：一个数据库文件，工具通过查询读取记录；不是需要手工打开编辑的文档。
  • JSON：结构化数据文件，适合程序读取。
  • Markdown / TXT / LaTeX / XML：文字文件；分别常用于报告、纯文本、论文源文和带结构的全文。
  • CSV / XLSX：表格数据文件；PDF / PNG / JPG / TIFF / SVG：论文页面、照片、图片或矢量图。
  • 工具记录：环境数据库中已有的结构化结果；最终答复：agent 输出的文字。
本页判定词说明：
  • Verifier：检查 agent 最终结果是否满足任务要求的程序。
  • 静态：直接读取最终文件或记录并按固定规则检查，不重新让 agent 做任务。
  • Codex：负责理解自由文字、提取信息和判断专业语义。
  • 模块：一个可以单独打分的任务目标，例如“文件存在”或“数据计算正确”。
  • 证据边界：已有材料最多能支持到哪一步，不能再往外推。
  • 口径：一个数字的定义、单位、样本范围和测量方式。
  • JATS/XML：一种带章节、图注和表格结构的论文全文文件；不是普通图片。
  • Lcapy：用于表示和计算线性电路公式的软件库；这里把它当作现成计算工具。
  • HAADF：另一种电子显微成像方式；任务要求把它和 GPA 的测量结果分开。
