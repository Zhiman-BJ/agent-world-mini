# Codex + 静态 Verifier 实现方案

## 目标

把每个任务拆成可独立评分的目标模块：

- **静态检查**负责确定性强、输入格式明确、重算成本低的内容。
- **Codex 检查**负责理解自由文字、提取事实、判断证据边界和专业合理性。
- **程序裁决**尽量接收结构化结果，不让 Codex 直接决定数字是否正确。

最终输出每个模块的 `pass / fail / missing / uncertain` 和分数。

## 1. 静态能力范围

静态 verifier 只做以下事情：

- 文件存在、路径、格式和可解析性；
- 已知字段、数组、标签、表格和状态的直接对照；
- 根据已确认的输入重算数字、统计量、单位换算和阈值；
- 集合、数量、来源路径和保护文件的变化检查；
- 固定算法的重算，例如 S21 聚类；
- 固定渲染器产物的格式、尺寸和内容一致性；
- 对 Codex 已抽取出的公式调用符号工具做等价性判断。

静态 verifier 不负责：

- 从任意中文中猜数字、单位、对象和条件；
- 判断一段话到底提出了什么主张；
- 判断引用是否真正支持科学结论；
- 判断开放方案是否合理或是否越过证据边界；
- 为任意画法建立复杂的视觉识别规则。

## 2. 模块统一格式

每个任务由若干模块组成，每个模块只检查一个目标：

```json
{
  "id": "S91.joint_claim",
  "goal": "判断三项指标是否被错误合并为同一器件性能",
  "input": ["task_text", "candidate_response", "evidence_table"],
  "judge": "codex_then_static",
  "weight": 8,
  "critical": true
}
```

模块执行结果统一为：

```json
{
  "status": "pass|fail|missing|uncertain",
  "score": 0,
  "evidence": [],
  "reason": "..."
}
```

`uncertain` 表示格式或语义无法可靠解析，不直接当作通过；可进入一次受限 Codex 复核。

## 3. 静态 / Codex 选择规则

### 直接静态

满足三个条件才直接静态：

1. 输入字段已经明确；
2. 正确规则是确定的；
3. 不需要理解自然语言上下文。

例：文件是否存在、矩阵是否有 146 个失败点、数组形状是否一致。

### Codex

出现以下任一情况，先用 Codex：

- 需要从自由文字提取数字、单位、对象、样本或条件；
- 同一个数字的含义取决于上下文；
- 需要判断一句话的主张和限定范围；
- 需要判断证据是否支持结论；
- 合法答案不唯一，不能和参考答案逐字比较。

### 混合

最推荐的模式是：

```text
Codex：把候选内容抽取成结构化事实/主张
静态程序：重算、比较、执行规则
Codex：只复核程序无法表达的语义边界
```

Codex 不直接输出总分，只输出受 schema 约束的抽取结果和证据片段。

## 4. 六个任务的模块拆分

### S24：符号电路

- 工作对象和旧/新网表归属：静态；
- 是否给出各要求的物理量：Codex；
- 公式、端口和变量抽取：Codex；
- 抽取后的公式等价、矩阵约束和禁止数值替换：静态符号工具；
- 旧新电路的负载解释：Codex。

### S21：晶圆聚类

- 输入矩阵、失败点和计数：静态；
- 12 组参数重算和优选：静态；
- 标签、噪声、簇统计和编号置换等价：静态；
- 文字取舍说明及物理含义边界：Codex；
- PNG 解码、尺寸和固定渲染结果：静态；开放画法的图像语义：Codex。

### S91：性能发布

- 文件路径、JSON 可解析性和明确字段：静态；
- 从报告提取数值、单位、测量类型和样本：Codex；
- 阈值、上下界、Vπ/VπL 和实测/仿真口径：静态；
- 联合性能声明、跨样本外推和发布措辞：Codex；
- 已抽取字段在 JSON、Markdown、答复之间的一致性：静态优先，歧义时 Codex。

### S56：文献选型

- 指定文件、行号和引用存在性：静态；
- 数字及其对象、条件、下限/近似性质提取：Codex；
- 比值、面积换算和效率重算：静态；
- 证据强度、跨论文可比性、因果边界和离子推荐：Codex。

### S81：GPA 证据边界

- 文件、图号和定位锚点：静态；
- 区域、时间、方法、剂量和观测量提取：Codex；
- 已结构化的阈值、标定和数值边界：静态；
- 是否把强度、化学、应变或束照变化混为一谈：Codex；
- 结论是否超出对象、时间和方法范围：Codex。

### S71：实验方案

- 两档配方、对照角色、温循协议和采样点等硬约束：静态；
- 图件路径和已结构化数据引用：静态；
- 从方案文字提取实验组、指标和晋级条件：Codex；
- 早期电阻与末期阻氧是否同时受约束：Codex；
- 方案是否把组级证据写成单件因果、是否科学可执行：Codex。

## 5. 胶水代码

### 输入

Verifier 接收：

```text
task_spec.json       # 模块定义、权重、关键错误规则
reference_facts.json # 已验证的事实和可重算输入
candidate_workspace  # agent 终态文件
candidate_response   # 最终文字答复
```

### 执行流程

```text
load task_spec
→ locate artifacts
→ run static checks that do not depend on interpretation
→ call Codex extractor for free-text claims
→ validate extractor JSON and evidence spans
→ run static checks on extracted facts
→ call Codex only for unresolved semantic modules
→ aggregate scores and critical-error caps
```

### Codex 接口约束

每次调用只给：

- 一个模块的任务条款；
- 相关参考事实；
- 候选答案的相关段落；
- 固定 JSON schema。

不让 Codex 重新浏览整个环境、重做任务或直接给总分。所有调用记录输入、输出、模型和耗时。

### 失败处理

- 文件缺失、解析失败：对应模块 `fail`；
- Codex 输出不符合 schema：`uncertain`，最多重试一次；
- 事实抽取成功但规则不满足：`fail`；
- 关键科学越界：触发该模块 0 分和总分上限；
- 未声明的额外保护要求不自动加入评分。

## 6. 落地顺序

1. 先定义通用 module schema、结果 schema 和日志格式。
2. 先实现 S21 静态数据模块，验证重算和标签等价。
3. 实现 S24 的 Codex 公式抽取 + 静态符号裁决。
4. 实现 S91 的事实表、联合声明和跨文件一致性。
5. 再实现 S56、S81 的证据边界模块。
6. 最后处理 S71 的开放方案语义判断。
7. 每个任务只准备少量关键错误样本，分别测试漏答、数字错误、范围越界和格式变体。

每个模块都保留独立分数和证据，避免用一个总判断掩盖 verifier 的具体缺口。
