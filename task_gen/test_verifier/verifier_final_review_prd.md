# Verifier 生成后的 Codex 最终修复 PRD

状态：待实现。适用于 Program 和 Codex+静态工具两种 verifier 生成方法。

## 1. 目标

生成管线完成后，增加一次最终 Codex 会话。Codex 读取任务原文、生成的 verifier、已有测试和真实证据，检查 verifier 是否真正按任务要求评分；发现问题后直接修改当前代码并测试，继续修复，直到通过或预算耗尽。

最终 Codex 的交付物就是修复后的 verifier。它不只写审查意见，也不把问题再拆回 designer 或 implementer。

## 2. 流程

```text
生成 verifier
  → 最终 Codex 读取任务、证据、verifier 和生成日志
  → 检查并直接修改代码
  → 运行测试和真实参考运行
  → 发现问题：继续修改并重测
  → 没有问题：冻结并交付
  → 预算耗尽仍有问题：记录失败，不交付为成功
```

最终 Codex 可以修改当前 verifier 中的 `main.py`、rubric、helper、模型调用文件或工具文件，也可以修改必要的生成管线代码；但不能修改任务原文、候选结果、参考结果来制造通过。


## 3. 必须检查的问题

最终 Codex 至少检查：

1. 每个任务要求是否被覆盖，是否出现重复计分或原文没有的额外要求。
2. 评分档位、权重、满分条件和归零条件是否自洽，满分是否可达。
3. `main`、rubric、helper、工具和模型调用之间的输入输出是否一致。
4. 文件路径、证据根目录、文件/目录类型和依赖是否符合真实运行环境。
5. 模型 prompt、输出格式、解析器和实际调用方式是否一致。
6. 检查器是否真的读取候选结果，而不是只看参考答案、工具成功标志或非空字段。
7. 真实参考运行是否能完整执行，所有 rubric/工具结果是否能正确汇总。

已知问题应作为检查提示：

- Program P07：组合数量和评分阈值可能写错。
- Program P12：归零条件和计数契约可能冲突。
- Program P16：长绝对路径容易导致模型引用错误。
- Program P18：模型输出说明可能与解析器不一致。
- Codex+工具 P02/P13：工具示例、路径根目录和输入字段可能与真实数据不一致。
- Codex+工具 P04/P10：不能把任务没有要求的解释文字当成扣分条件。
- Codex+工具 P03：工具自行复算的专业数值与原环境不一致时，必须先定位口径，不能直接改成参考答案。

这些案例用于提醒检查方向，不写成针对任务 ID 的硬编码规则。

## 4. 修复原则

- 任务原文是唯一要求来源；参考结果只能作为核对材料。
- 低分不自动视为 verifier 错误，满分也不自动视为 verifier 正确。修改必须有任务要求、证据或实际运行错误作为依据。
- 可以修复代码、接口、路径、prompt、解析器和测试；不能为通过而放宽任务标准或硬编码参考答案。
- 自由文字、公式、单位和专业等价判断仍交给 LLM/Codex；不能用简单关键词或正则替代必要的语义判断。
- 明确的结构化计算优先使用静态方法。
- 文件缺失要结合任务判断是未完成、合法替代还是检查器无法判断；不能一律判 0，也不能一律报错。
- 遇到无法可靠判断的专业算法差异，保留问题并说明原因，不强行修改成某一方结果。

## 5. 测试要求

最终 Codex 至少运行：

- 生成包的语法、接口和 schema 检查；
- 所有 rubric 或工具的实际调用测试；
- 一次完整参考运行，使用应用端相同的 context、SDK、路径和依赖；
- 必要的关键缺失/错误样例，确认异常边界不会被吞掉。

Program 的完整测试必须执行全部 rubric 并由宿主重新汇总。Codex+工具的完整测试必须由主 Codex 按固定 rubric 调用工具并提交结果。生成阶段的最终测试不触发正式应用的整任务 fallback；发生错误就继续修复，最终仍失败则记录失败。

## 6. 成本和记录

最终 Codex 的所有调用、修改、测试、耗时和 token 都计入**生成成本**，与后续应用 verifier 的成本分开。记录：

- 最终 Codex 使用的模型和推理强度；
- 每轮修改和测试结果；
- 最终交付文件哈希；
- 未解决的问题和失败原因。

最终交付后，应用阶段使用同一份冻结 verifier；重复应用测试不能重新生成或修改 verifier。

## 7. 最小实现范围

在现有两条生成管线的生成完成位置增加一个最终 Codex 步骤即可：

```text
generate
  → final_codex_review_and_fix(current_verifier, task, evidence)
  → tests
  → freeze_and_return
```

复用现有 Codex 调用、sandbox、测试、日志和费用记录代码。暂不新增复杂的 reviewer JSON、版本树、designer/implementer 路由或通用修复框架。

完成标准：最终 Codex 能读取当前生成结果，发现问题后直接修改并测试；测试通过时交付修复后的 verifier，预算耗尽或仍有错误时明确返回失败；生成成本和应用成本可分别统计。
