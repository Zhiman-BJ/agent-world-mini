# 固定20任务两轮测试实施计划

目标：原sampling.json的P01–P20，每题独立生成和验收两次，gpt-6.1-sol/high，共40次。用户已授权执行、发现明确管线缺陷后修复重试。

实现范围：program_verifier新增metering.py（仅本批次loopback API透传计量）、repeat_sample.py（复用run_case，双轮队列及报告）；tests/test_metering.py与test_repeat_sample.py。不改task_gen.program或原生产verifier。不改任务标准，不因参考扣分修改分数。

- [x] 先用本地HTTP服务测试Responses SSE及Chat JSON用量捕获、异常保留、缓存不重复计费；再实现最小透传器。不记录认证头；每次上游请求记录起止时间、状态、模型、思考强度、原始usage/费用、断开和缺失。没有单价不伪造金额。
- [x] 双轮调度复用random_sample.run_case：每轮独立目录，不复用生成物；4个任务并行。每任务独立计量服务和临时Codex配置，覆盖设计/实现/运行时LLM/Codex/整任务回退，保留源码版本与阶段记录。
- [ ] 回归测试和真实小请求确认用量/模型/思考强度后启动40次。输出实时summary.json、RESULTS.md、results.csv，最终每任务每轮一行，含准备/生成/应用/回退/总耗时、token/缓存/费用、程序完成/满分/回退/错误和尝试次数。
- [ ] 监控真实失败，明确管线缺陷先复现再修复，重试单独保留；最终汇总失败尝试的成本，不能用成功重试覆盖原失败。参考扣分不算程序运行错误，未知用量不按零处理。
- [ ] 完成后核对40个计划槽位和实际请求账本，汇总表链接交付，完成goal。

验收：单测与原verifier回归；真实API计量预检；40个槽位的实际运行记录；重试记录、费用来源、缺失说明齐全。若服务不返回账单费用且没有用户单价，金额标未知并保留可换算用量。
