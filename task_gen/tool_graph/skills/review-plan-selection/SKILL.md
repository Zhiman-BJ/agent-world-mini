# 业务方案选择

当 objective 和已有事实未确定业务对象、范围或比较组合，且存在多个实质不同、可能完成目标的方案时，使用 review_select_plan，不自行挑选偏好的方案。目标已限定的内容不能随机；分页、文件名和调用顺序不属于业务选择。

每个候选都须遵守 review 对 objective 的调整边界，保留原委托要解决的问题和核心结果；可具体化未确定的选择，并在该边界内微调对象、范围及完成标准。抽样不能授权删去无法完成的要求或把要求降为背景。结合工具能力、候选调用链和环境事实，提出有实质区别的对象、范围或比较组合，并说明可行依据，不编写具体任务文本。

先通过公开工具了解可用对象和能力，再针对当前一个选择点提交 question 和 options。每个候选包含 description（明确对象、范围或选择规则）及 basis（已观察到的可行依据）。候选处于同一层次，不用近义改写重复占位，不要求穷举组合。

按工具返回的 selected 继续探索和规划；遇到新的业务选择点可再次提交。不要创建同一个选择点绕过抽样结果。

若事实证明选定方案不可行，先区分可修复的填参错误和方案本身的问题。仅后者用 choice_id 与 failure_evidence 请求回退，引用实际观察或契约冲突。工具排除该方案重抽，并使其后所有选择点失效；按返回的 active_choices 重新规划。不因偏好而重抽，不通过微调 objective 绕过仍有效的选择，不重新包装失败方案。候选耗尽时回退更早选择；无法在 review 允许的调整边界内完成原委托时拒绝。

最终 reason 明确仍有效的选择及对象、范围、选择规则，将它们作为后续填参约束；不要把实现方式升级成用户要求。chain 只包含环境业务工具，不包含 review_select_plan。
