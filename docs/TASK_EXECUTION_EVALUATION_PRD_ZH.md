# 任务真实执行审核 PRD

## 1. 背景与目标

系统已经能够生成任务，并让 Agent 在包含多项文件资源的环境中调用带 Python
内部实现的工具。下一步需要判断：Agent 的一次真实执行是否在语义上完成了任务。

审核的金标准是：

> Agent 完成了任务文本提出的全部实质要求，并且没有破坏环境中原有的正确数据。

审核结果必须可追溯到具体任务要求和实际执行证据。

## 2. 输入及其作用

| 输入 | 作用 |
| --- | --- |
| 任务文本 | 唯一定义需要完成什么，是成功条件的来源 |
| 环境资源和公开工具契约 | 解释可用资源、工具能力及业务语义 |
| 参考调用链、参考 workspace 和参考回答 | 提供一种已知成功方式，用于生成、校准和验证审核标准 |
| 实际调用轨迹、最终 workspace 和最终回答 | 构成被审核执行的全部证据 |

参考执行不是标准答案，只用于说明一种已知成功方式。

实际证据分为三类：调用轨迹、初态与终态 workspace、最终回答。每项任务要求只使用与其
有关的一类或多类证据，不要求所有要求都同时具备三类证据。

## 3. 成功判定

任务先拆成可独立判断的原子要求。所有必需项都通过，整项任务才通过；任一必需项失败，
整项任务失败。允许存在多种语义等价的完成方式。

只有任务明确要求某个过程或先后顺序时，才检查调用过程。是否必须修改或生成文件也由
任务文本决定：查询、计算或返回结果的任务可以在 workspace 不变时完成；要求保存、写入
或改变状态的任务必须有相应的持久化结果。

判定比较的是业务语义，不是与参考执行做字面一致性比较。

## 4. 审核流程

```text
任务文本 + 环境 + 参考执行
  -> 拆分原子要求并确定每项所需证据
  -> 生成任务专用 verifier
  -> 用参考执行和少量反例校准 verifier
  -> 冻结 verifier
  -> Agent 从相同初态真实执行
  -> 收集调用轨迹、最终 workspace 和最终回答
  -> 逐项审核并汇总整项结果
```

参考执行应当通过冻结前的标准。若参考执行不能通过，或任务文本不足以形成可判断的标准，
应先处理任务或审核标准问题，不得把问题归因给 Agent。

路径、数量、结构变化等可机械验证的事实优先用确定性逻辑检查。LLM 只负责预先定义的
原子要求中的语义判断，不能自由发挥后给整项任务打一个总分。审核标准冻结后，不能因
Agent 采用了不同路径而改变。

## 5. 证据规则

### 5.1 调用轨迹

- 工具返回成功只证明一次调用成功，不证明任务已经完成。
- 调用结果、业务错误和执行异常都属于证据。
- 除非任务明确要求过程，否则调用轨迹只用于证明结果和因果关系。

### 5.2 Workspace

- 比较初态与终态的路径、文件类型和业务内容，忽略普通文件系统时间变化。
- 结构化文件优先按结构和业务语义检查；易变字段不按字面值判定。
- Workspace 发生变化不等于变化正确，没有变化也不天然代表失败。
- 对专业文件，可以在最终 workspace 的副本上调用环境已有工具提取语义证据；审核操作
  不得污染 Agent 的最终 workspace。
- 状态修改必须同时满足目标结果成立，并保护同一资源内与任务无关的原有记录和业务不变量。

`resource_constraints` 只能作为资源范围和副作用线索，不能单独证明业务目标完成。

### 5.3 最终回答

- 回答声称成功不等于实际完成。
- 回答中的业务事实必须能由调用结果或最终 workspace 支持。
- 任务明确要求返回的信息必须出现在回答中；其余措辞不参与成功判定。

### 5.4 跨证据一致性

同一业务对象在调用轨迹、workspace 和回答之间必须能够对应。动态 ID 等运行时值按其
所指向的业务对象核对，不按标识符的字面值判断。

## 6. 结果与归因

每项原子要求输出 `pass`、`fail` 或 `indeterminate`。任一必需项为 `fail`，整项结果为
`fail`；否则任一必需项为 `indeterminate`，整项结果为 `indeterminate`；全部必需项为
`pass` 时才是 `pass`。

非通过结果另行记录归因：Agent 执行问题、基础设施问题或审核标准问题。环境故障、证据
采集失败和审核器错误不能统计为 Agent 失败。每个结论必须保留逐项理由及其使用的证据。

## 7. 范围边界

- 基础完成判定不评价工具数量、执行成本、效率、UX、安全或政策指标。
- 多次试跑和 `pass@k` 只衡量稳定性，不定义单次执行是否完成。
- 本阶段不建设适用于所有专业格式的通用解析框架，按实际环境复用已有工具和最小检查逻辑。
