# 项目文档

Agent-World Mini 将真实数据和领域工具组织成可执行环境，在其中设计任务、运行模型、独立验收并导出训练轨迹。
文档按“先理解架构，再执行操作，最后查配置与排错”组织。以下说明对应当前源码；历史批次按各自冻结版本复现。

## 第一部分：理解系统

### 1. 总体架构

先读[系统架构](SYSTEM_ARCHITECTURE_ZH.md)，理解环境、工具交付、任务、求解、验收和训练数据的关系。
本仓库负责环境与轨迹，外部 `agent_train` 工程负责梯度训练和权重部署。

### 2. 执行与隔离

- [Harness 接入](HARNESS阶段接入说明.md)：工具契约、任务工作区、私有状态与开发 API。
- [MCP 与工具调用](MCP与工具调用代码地图.md)：模型如何看到工具，一次调用经过哪些模块。
- [工具运行时与隔离](TOOL_RUNTIME_ZH.md)：后端如何选择、哪些路径使用 bubblewrap、Verifier 为什么单独隔离。

### 3. 业务流程

- [任务生成](TASK_GENERATION_ZH.md)：Program、单作者设计与 Tool-graph 的职责。
- [测评与独立验收](EVALUATION_ZH.md)：求解器与 Verifier 的关系、证据和成功口径。
- [蒸馏与训练数据](DISTILLATION_ZH.md)：教师执行如何转成可审计的训练窗口。

## 第二部分：实际使用

### 1. 跑已有任务

按[快速上手](QUICKSTART_ZH.md)配置运行环境，先完成一题求解与验收。
再按[测评操作](EVALUATION_ZH.md)扩大并发、进行双模型对照、重新判分或导出轨迹 HTML。

### 2. 设计任务与接入工具

- [单作者任务设计](TASK_DESIGN_ZH.md)：作者材料、参考调用列表、会话内校验和提交。
- [Program 三阶段](PROGRAM_PIPELINE_ZH.md)：从交付 binding 到任务与参考程序。
- [Harness 使用案例](HARNESS使用案例.md)：直接调用工具、工具发布、任务生成和 MCP 执行示例。

## 第三部分：配置与维护

- [运维排错](OPERATIONS_ZH.md)：启动检查、恢复、集群访问与常见故障。

## 文档约定

架构说明解释职责、数据与边界；操作说明提供代码、命令及结果检查；配置表集中维护参数默认值。
模块 README 只保留导航，现行说明集中在本目录，不保留废弃方案、历史试跑报告和跳转页。
API key、登录密码、kubeconfig 私钥不进入文档。历史实验的协议和成绩以对应运行目录为准。
